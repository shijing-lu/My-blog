## 3. 关键修复与设计变更

1. **鉴权**：使用 owner identity，委派的 top 管理员仍被拒绝。
2. **服务端存储**：由初稿的多张 SQL 业务表改为 `cadence_records` JSON 封装；保留实体校验，减少双数据库字段转换和备份兼容风险。
3. **同步**：由初稿的游标/deviceId/batchId 改为全量快照 + 逐实体 UUID CAS + 内容幂等；基线在确认后更新，客户端编辑期间不被网络返回覆盖。
4. **导入**：去掉合并导入后的错误行数断言；默认跳过重复编号，事务内保存原内容快照，失败回滚。
5. **历史引用**：执行/复盘记录允许关联的任务或周期已被回收站永久清理，保留原字段和正文；活动任务、待办仍校验必要引用。
6. **执行**：不再只扫描近 24/48 小时寻找活动记录；暂停时长进入统一计算口径，手动补录校验重叠与时间边界。
7. **复盘**：新条目按周期和起点生成稳定编号，重写已删除格子时复用原编号；增加独立历史内容列表。
8. **XY**：设置页可以创建多套配置与矩形分区，看板按所选配置过滤待办，按真实分区边界绘制。
9. **助手**：本地规则优先；改用 Zod 4 JSON Schema 和博客服务端配置；前端不存密钥。
10. **视觉**：移除独立主题、纸纹、倾斜和手绘输入线；颜色、字体、圆角、卡片与输入组件跟随博客。
11. **样式编译**：构建曾提示 React 入口中的 `@theme` 未被 Tailwind 处理，已移入全局 CSS 的语义 token import，区域样式继续隔离。
12. **统计**：总览查询包含昨天供对比，显示今日值时独立过滤，避免把两天的投入相加。

## 4. 使用步骤

1. 登录站主账号，点击主导航“日程”。首次打开会创建本机副本与默认优先级坐标，业务数据保持空白。
2. 在计划、今日计划或时间轴录入内容；执行页可计时或补录，复盘页写回顾。
3. 迁移原 Cadence 数据时，在源应用导出 JSON，再到日程设置的“数据管理”选择文件，查看摘要与重复策略后确认。
4. 多设备使用：各设备进入“设置 → 设备同步”，检查本地/远端数量，再连接。两台设备必须使用同一个服务端数据库。
5. 同一记录双方有修改时，到设置比较版本，选择本地或远端；历史副本可查看、下载和恢复。
6. 原日历仍位于 `/calendar`，原日历待办和 Cadence 待办为不同数据。

浏览器、端口、域名和 Electron 用户配置不同，通常对应不同 IndexedDB 副本；它们需要通过同一同步端点合并，不能把“换端口后为空”解释为原数据被删除。

## 6. 部署、数据库和回滚

- 本机开发启动沿用 `pnpm dev`，访问 `/schedule`。
- SQLite 日程接口会新增自己的表，无需对现有数据库执行全量 `db:push:dev --force`。
- PostgreSQL 上线前备份数据库并审阅完整迁移链，再执行项目正常的 PG 迁移流程；`0017` 文件已经提供，本次未执行。
- 需要桌面端与网站共用云端时，使用桌面已有 `SYNC_DATABASE_URL` 配置；不要把开发 SQLite 当成云端权威数据。
- 问题回退可在设置暂停同步，保留本机业务数据、基线、冲突副本和服务端墓碑。回滚页面/API 不删除新表。
- 不覆盖正在运行的桌面便携包。打包是独立交付步骤，需应用保存并退出后进行。

## 7. 范围边界

未增加多人协作、公开分享、第三方日历订阅、邮件/系统提醒或新的原生客户端。网页没有 Service Worker 离线冷启动；当前打开的网页与本地桌面服务支持离线副本操作。全量同步、设备本地的历史副本和整批业务约束拒绝均是本期明确的实现边界。
