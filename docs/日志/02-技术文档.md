# 日历日记与 AI 整理：技术文档

## 数据与接口

复用 `diary_entries` 的日期唯一约束及 `/api/diary` 的 GET/POST，继续以完整 MDX 管线返回 `contentHtml`。双击无记录日期时，通过仅在不存在时插入的创建接口写入空白日记，避免并发请求覆盖已有正文。`/api/diary/generate` 继续支持 `missing` 历史补缺和 `replace` 当日覆盖；`/api/diary/source-dates` 返回待补日期和上海时区的今天。所有日记响应设置 `private, no-store`，路由中间件统一限制站主。

## 日历交互

日期格保留可访问的链接目标。客户端延迟单击导航以判定双击：单击跳转并选中日期，双击取消单击导航并打开浮层。选中日面板提供显式按钮，供触屏与键盘使用。浮层读取 `/api/diary?date=...`；缺失时原子创建，再读取正文。阅读区使用服务端渲染 HTML 和文章 `prose` 样式。编辑区复用 `MarkdownEditor` 的 WYSIWYG 模式，浮层内保存至 `/api/diary`，成功后重新读取渲染结果。关闭未保存编辑时提示，避免内容丢失。

## 来源关联与安全

`readSources` 为每条动态和随心录带入稳定 ID。传给 AI 的来源使用短引用码而非 URL，要求每条归纳以引用码声明其来源。服务端解析并校验引用码，仅从当日查出的 ID 构造链接；未通过校验的引用不能变成链接，不能接受模型提供的外部地址。生成内容最终保存为普通 Markdown，逐条附 `[动态原文](/moments/ID)` 或 `[随心录原文](/quick-notes?note=ID)`。动态单条页面按公开或私密权限显示；随心录页面按 `note` 参数打开对应浮层。

## AI 与批量流程

沿用站点 AI 配置、上海日期边界、来源输入上限、请求超时和完整流结束校验。保留风格提示词与禁止编造规则。历史批量由日历页面顺序发请求并显示进度；离开页面取消在途请求，重新进入后重扫缺失日期。`missing` 在保存时原子插入，保护扫描后手工创建的日记；`replace` 仅允许今天，AI 完整返回后再写入。

## 兼容与界面

导航移除独立“日志”，`/diary` 重定向到 `/calendar`。日历右侧选中日面板的旧编辑链接改为打开浮层，保留其他日历功能。旧 `/calendar/diary` 跳转到日历对应日期并自动打开浮层。日记日期标记及预览仍只在站主会话可见。
