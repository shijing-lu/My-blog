# 日历日记与 AI 整理：需求文档

## 目标与入口

日历是每日记录的统一入口。日记与 AI 整理的日志共用 `diary_entries`，每个日期至多一篇。取消顶栏“日志”和独立时间轴入口；旧 `/diary` 地址跳转到日历。

- 日历日期单击仍选中当天并显示待办、重要日期等信息；双击打开当天日记浮层。没有日记时创建空白日记。键盘和触屏用户可通过选中日面板的“打开日记”按钮完成同样操作。
- 浮层先以文章阅读样式显示 Markdown。点击“编辑”在同一浮层切换到可视化编辑器，支持现有 Markdown 扩展语法。保存后回到阅读状态并更新日记标记与选中日信息。
- 日历提供“生成当日”和“生成以前所有日期”。前者按上海日期生成今天并覆盖今天现有日记；后者逐日补写过去有来源、但尚无日记的日期。已有手工内容均跳过。
- 没有来源不调用 AI；失败、超时、断流或空输出不改动原文。批量生成显示进度、成功、跳过和失败日期；重新运行可补缺。

## 生成内容与来源

来源包括当天公开及私密动态、随心录。AI 只根据来源明确的信息归纳，不编造行动、人物、地点或媒体细节。每条生成的记录后附来源链接；一条归纳涉及多个来源时附多个链接。动态链接定位具体动态；随心录链接打开对应原记录。链接目标由服务端按来源 ID 生成并验证，AI 无权指定任意 URL。

“设置 → AI 助手”的日志风格继续控制之后的生成：简洁客观、第一人称日记、原文摘录为主。调整风格不改写已有日记，手工编辑也不受限制。生成使用站点当前配置的 AI 服务商和模型。

## 权限与兼容

日记、AI 整理内容、日期标记、预览及接口仅站主可访问。日历的待办、重要日期继续遵循原有权限。现有日记数据保留，旧 `/calendar/diary` 跳转至日历对应日期的浮层。

## 验收条件

1. 单击日期选中，双击打开日记；无记录时创建；选中日按钮在触屏和键盘上可用。
2. 阅读、就地编辑、保存和再打开保持 Markdown 扩展语法与文章阅读效果。
3. 全量仅补缺失历史日期；当日生成覆盖；无来源、失败和空结果不破坏数据。
4. 生成条目链接到具体动态或随心录，私密来源仍受原页面权限保护。
5. 上海午夜前后日期归属正确；非站主无法看到日记内容、标记或调用日记 API。
