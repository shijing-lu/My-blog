# 文章编辑与便携版更新提示：需求及实施记录

## 已确认的产品规则

- `release/portable` 的便携版启动时不显示版本更新弹框；安装版仍检查更新。便携版继续覆盖固定目录。
- 文档目录中的“新增文章”立即在当前目录创建空白文章，选中并进入可视化编辑。空白文档沿用现有公开规则，访客可见。文件夹和已有节点的编辑、移动弹框保留。
- 首页右侧工具栏的新增文章立即持久化空白草稿，进入独立编辑页。草稿仅管理员可见，主动发布后才进入公开详情、列表、搜索、订阅和站点地图。
- 已发布的首页文章修改后保存即对访客生效。文章编辑保留类型、分类、标签、摘要、封面、访问密码和思维导图相关能力。
- 文档文章和首页文章使用同一套 Markdown 可视化编辑能力；编辑页能切换预览，首次进入编辑即显示可视化内容。

## 现状和技术方案

| 领域 | 现状 | 改动 |
| --- | --- | --- |
| 桌面版 | `desktop/main.cjs` 对所有打包版运行 `checkVersion()` | 便携构建在 `resources` 放标记，主进程检测标记后跳过检查 |
| 文档新增 | `doc/[id].astro` 打开标题/内容弹框；API 拒绝空正文 | 创建接口接受空正文；新增按钮直接创建、刷新树、导航到节点并打开编辑器；标题在文章页可修改 |
| 首页新增 | `/edit/new` 只生成 UUID，首次保存才入库 | 创建草稿接口先入库再重定向；失败时留在当前页并显示错误 |
| 首页编辑 | `LiveEditor` 使用 Markdown 编辑器但未启用 `wysiwyg` | 抽取/复用编辑及预览机制，并以文章专属面板呈现元数据 |
| 公开读取 | `articles` 无发布状态，所有记录公开 | 双数据库增加 `published`，旧记录为已发布，新建记录为草稿；公开查询统一过滤，管理员查询保留全部 |
| 同步 | `articles` 为 LWW 同步表 | 双端字段一致，迁移后才启动包含新列的同步 |

## 开发和提交顺序

1. 提交本需求、迁移和验收记录。
2. 实现便携标记及启动过滤，提交 `fix(desktop): ...`。
3. 复用文档与文章的可视化编辑、预览和保存状态，提交 `refactor(editor): ...`。
4. 文档文章即时创建和页面内改标题，提交 `feat(docs): ...`。
5. 双库迁移、草稿创建/发布、所有公开读取过滤及同步字段，提交 `feat(articles): ...`。
6. 构建便携版并覆盖 `release/portable`。已有工作区改动须按代码块或明确路径暂存，禁止笼统暂存。

## 失败处理与验收

- 创建失败不导航，也不产生只有客户端知道的节点；保存失败保持当前内容并提示用户。
- 发布前要求有效标题和非空正文；自动保存不改变发布状态。旧文章迁移后仍公开。
- 访客无法通过详情 URL、列表、标签、归档、搜索、RSS 或站点地图读取草稿。管理员列表和编辑页可读取草稿。
- 桌面两端同步保留 `published`，不同端创建或发布后状态一致。
- 便携版首次及再次启动均不弹“有新版本”；安装版仍保持更新检查。
- 编辑器首次打开、编辑/预览切换、空内容、密码设置和切换、标签等文章专有功能均可使用。
