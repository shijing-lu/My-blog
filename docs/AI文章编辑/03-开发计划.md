# AI 文章编辑：开发计划

日期：2026-10-08。当前仅完成需求和技术规划；以下是开发阶段安排。

## 1. 实施顺序与完成条件

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| P0 接入兼容性 | 锁定 Pi 版本，Provider Adapter，工具能力和预算检查 | 当前服务商能返回完整文本与真实工具调用；明确模型上限 |
| P1 技能运行时 | 导入两个完整技能包，注册、读取、版本和设置管理 | 修改 SKILL.md 后新任务能读取新规则，无需重建 |
| P2 编辑器桥接 | 当前目标、最新稿、选区及嵌套位置映射 | 两种文章共用；Callout、分栏、表格输入和选区不丢失 |
| P3 选区编辑闭环 | 右键入口、聊天、候选、检查、提交、撤销 | 一段文字可在原位自动修改并保存，一步撤销 |
| P4 整篇编辑与检索 | 右侧聊天绑定全文、只读检索、技能路由、长文分块 | 原文覆盖完整，来源可追溯，只有当前篇被修改 |
| P5 集成与交付 | 旧 AI 功能迁移、故障处理、数据库与依赖打包 | 网页与 portable 可运行，原有聊天、记忆、日记可用 |

先完成最小的选区读写闭环，再扩展全文和长文处理；不同时更换编辑器内核或重建文章存储。

## 2. P0：Pi 接入与能力检查

计划新增 `src/lib/ai-runtime/`，集中 Provider 配置、请求取消、事件归一化、结果完成状态和 usage。

1. 安装并锁定 `@earendil-works/pi-ai` 与 `@earendil-works/pi-agent-core`。
2. 根据现有配置建立自定义 OpenAI 兼容 Provider，保留密钥、地址和模型。
3. 扩展连接检查：纯文本、一个无副作用的工具调用、流式完成和输出预算。
4. 确定当前中转模型是否能执行工具；连接成功不等于工具能力成功。
5. 新增文章编辑独立参数：开关、可选编辑模型、输出/上下文预算、任务步数上限。
6. 先迁移普通聊天并保持现有 SSE，再迁移摘要与日记。

当前 `deepseek-v4-flash` 是候选运行模型；未经真实验证不宣称已适合 Agent。若工具支持不足，保留普通聊天可用，编辑入口说明缺少能力；站主可在设置选择已验证的模型。不会在后台擅自更换模型。

## 3. P1：真实技能库

计划新增 `src/lib/ai-skills/` 和两个完整默认技能包。

1. 从站主提供的两个技能路径导入原文，记录来源和指纹。
2. 实现元信息发现、完整文件读取、关联资源读取、版本固定和加载去重。
3. 注册 `read_skill`、`read_skill_resource` 和显式技能选择。
4. 实现 `note-normalizer` 向 `my-blog-structured-notes` 的技能链加载。
5. 增加「设置 → AI 助手 → 技能」：完整源码编辑、导入、导出、开关、历史恢复。
6. 实现技能文件变更后的缓存失效；保存接口带基准版本，避免编辑旧稿覆盖新规则。
7. 补齐 SQLite/PostgreSQL 版本库与同步策略；分叉版本保留并显示。
8. 桌面增加本机目录挂载适配器，登记两个技能；每次新任务读取文件指纹并固定快照。网页与本机共用同一读取工具。

技能正文不写进 TypeScript 的长提示词常量。环境适配、权限与工具参数校验属于运行时代码，不把格式模板重新实现成一套业务函数。

## 4. P2：编辑器上下文

主要接入文件：

- `src/components/admin/MarkdownEditor.tsx`
- `src/components/doc/DocInlineEditor.tsx`
- `src/components/admin/cm-context-menu.ts`
- `src/components/admin/cm-callouts.ts`
- `src/components/admin/cm-columns.ts`
- `src/components/admin/cm-visual-directives.ts`
- `src/components/admin/cm-table.ts`

工作项：

1. 扩展句柄以获取根稿和版本，注册当前文章目标。
2. 设计持久选区目标，处理子编辑器到根源码映射。
3. 加入 pending input 刷出机制，尤其表格的 300ms 防抖内容。
4. 加入单次 AI 修改事务、历史隔离及保存已确认标记。
5. 处理浮层焦点、已打开原生 dialog 的顶层容器、Esc、切换文章和 Astro 路由销毁。
6. 当前正文自动保存改用可携带版本的顺序队列，消除迟到写入覆盖问题。

## 5. P3：选区修改

1. 编辑器原有右键菜单增加「使用 AI 编辑」。
2. 复用现有 AI 浮层视觉，加入文章、范围、任务状态和修改反馈。
3. 注册选区候选工具；上下文包含必要邻文和提纲，缺少上下文时读取当前稿。
4. 完成候选校验、原子提交、根事务应用和目录更新。
5. 实现同页撤销和持久快照恢复。
6. 首先闭环普通段落，然后覆盖 Callout、分栏、代码块、公式与表格单元格。

成功自动应用，不增加强制的「确认替换」步骤。冲突场景保留候选并提示重新生成，不能用成功动画掩盖失败保存。

## 6. P4：全文整理和按需参考

1. 右侧 AI 在编辑模式绑定当前篇；问答与修改结果区分。
2. 注册有权限的站内搜索与正文读取工具，UI 展示来源。
3. 整篇技能整理先建立内容覆盖清单，按技能模式组织输出。
4. 长文章按完整结构分块，跨块编号、目录、复习索引统一汇总。
5. 检查模式不明确时，通过聊天澄清，不持有一个等待用户数分钟的服务器请求。
6. 多块只形成一份候选；全部成功并通过检查后一次提交。
7. 第二轮聊天基于最新的已应用文章，不把第一轮旧稿当成当前稿。

## 7. P5：集成与发布

修改点还包括：

- `src/components/ai/AiChatFloat.tsx`：编辑上下文、编辑任务事件、来源与加载技能状态。
- `src/pages/admin/settings/ai.astro` 及现有设置浮层：编辑参数和技能管理。
- `src/lib/ai-config.ts`：旧配置兼容，独立预算与能力信息。
- `src/pages/api/ai/*`、`src/lib/diary-log.ts`：共享 Pi Adapter。
- `src/lib/route-permissions.ts`：新接口统一站主权限。
- `src/lib/pending-article-saves.ts` 与 `latest-save-queue.ts`：版本化顺序保存。
- `db/schema.sqlite.ts`、`db/schema.pg.ts`、部署迁移及 `src/sync/tables.ts`。
- 桌面依赖闭包打包脚本：Pi 依赖与完整技能资源。

发布前完成项目类型检查和网页/桌面构建，记录现有问题和新增问题。当前计划没有运行任何真实 AI 请求、自动测试或构建。

桌面交付只覆盖 `release/portable`。构建前若应用运行，通知站主保存并退出；不直接结束进程。原生 Android 的编辑 UI 和相应 APK 不在本轮首版交付中。

## 8. 验收清单

| 场景 | 预期 |
| --- | --- |
| 未保存正文刚改过 | AI 读取最新稿，不能读成数据库旧内容 |
| 选区打开浮层后失焦 | 原选区范围保持，不替换到新光标位置 |
| Callout / 分栏 / 表格 | 选区外内容和容器结构保留，表格待写回输入不丢失 |
| 普通聊天或解释 | 没有文章改动 |
| 全文明确修改请求 | 自动覆盖、保存、刷新目录，发布状态不改变 |
| 技能自动路由 | 有真实文件加载记录，输出遵守该版本的模板 |
| 显式指定技能 | 必须加载对应技能，不只按名称猜测 |
| 编辑技能后新任务 | 读取新版本；旧任务版本固定 |
| 修改本机挂载的 SKILL.md | 新任务加载修改后的源文件；路径失效时报错，不静默使用旧副本 |
| 其他文章检索 | 可见来源，正文只读，当前篇仍是唯一写目标 |
| 模型输出截断或流中断 | 原文保留，候选不提交 |
| 模型报错 / 内容校验失败 | 可见失败原因，正文不变 |
| 生成期间继续输入 | 不覆盖新文字，保留候选和冲突状态 |
| 保存队列存在旧请求 | 版本条件阻止迟到请求覆盖 AI 结果 |
| 提交成功但返回丢失 | 查询任务确认结果，幂等重试不重复修改 |
| 切换文章 / Astro 路由 | 旧任务不写入新文章，取消生成并解除上下文 |
| 撤销与恢复 | 一步回退该轮；刷新后可恢复，遇到新版本不强制覆盖 |
| 超长技能和正文 | 明确分块或预算提示，不静默丢规则或丢原文 |
| 非站主直接调用 API | 被拒绝，无私密内容和候选正文泄漏 |
| 普通聊天、摘要、日记 | Pi 迁移后保留原功能、风格及记忆策略 |
| portable 自包含 | 不依赖开发目录也能读取技能并运行 Pi |

## 9. 工作量判断

这是中等偏大的跨模块功能，难点是嵌套选区映射、保存并发、长文完整性和技能可维护性。按阶段交付比一次上线所有能力更容易定位问题。

粗略工作量：接入与技能 2–3 个开发日；选区闭环与嵌套适配 2–4 日；全文、检索与长文 2–4 日；集成与交付 1–2 日。合计约 7–13 个开发日，属于规划估算，并非模型运行时间或承诺工期；P0 兼容性结果可能改变安排。
