# Android 云同步配置修复

## 原因与需求

创建空白 Android 站点仅保存本地密码，不含 SYNC_DATABASE_URL；现有同步页没有配置入口。syncStatus 的 cloudConfigured 只在装配端点后变为 true，缺少连接串时 startSync(false) 仍返回 started=true，造成“正在启动”和配置状态误导。报错引用 Windows config.json 路径，不适用于手机。

URL 指 PostgreSQL 连接串，形式为 `postgresql://用户:密码@数据库主机:5432/库名?sslmode=require`，不是 https 网站地址。主库对应正式站 DATABASE_URL，备库对应 DATABASE_URL_FALLBACK；客户端存为 SYNC_DATABASE_URL 与 SYNC_DATABASE_URL_FALLBACK。不得把真实连接串写入源码或 APK。

## 实施顺序

1. 新增仅本地运行环境、仅站主可访问的配置接口，GET 仅返回配置状态；保存格式验证、保留留空字段、显式移除备库、原子持久化并立即更新运行时环境。同步进行中不允许更换连接。
2. 同步设置提供主库/备库密码输入、保存、只读连接测试、显式复制配置到另一设备以及粘贴导入。未配置时禁用同步，不要求操作系统内 JSON 文件。两种界面风格共用入口。
3. 状态从当前环境读取；未配置同步在启动前拒绝，文案引导设置；有配置的运行任务仍为非阻塞、可轮询，保留现有冲突副本和双库镜像语义。
4. 使用隔离目录及模拟数据库验证持久化、权限、无敏感回显、重启恢复、缺配置快速拒绝、失败状态及两个连接测试。构建签名 Android 更新包，真机结果单独记录。

## 存储与边界

Android runtime 显式传递配置路径；桌面沿用 APPDATA/byqx-blog-desktop/config.json。配置不进入 settings 表及云同步，不改变本地 SQLite、文章内容或同步镜像。连接测试只执行 SELECT 1，不执行上传/覆盖。设备传递采用 AES-256-GCM 加密配置与独立文件口令：桌面导出文件，Android 复制加密文本，两端均支持文件或粘贴导入。普通 GET 不返回凭据，导出也不返回明文连接串。原生文件授权/系统剪贴板仍需 Android 真机验证。

## 使用方法

1. 在现有应用上安装签名一致的 Android 1.1.2（versionCode 7）更新包，保留本地文章。不要卸载旧应用。
2. 用站主账户登录，打开「设置 → 云端同步」。
3. 展开「从另一台设备导入／导出连接配置」，选择 `.byqx-sync` 加密文件并输入独立配置口令，点击「导入并保存」。也可以直接粘贴主备 PostgreSQL 连接串后保存。
4. 点击「测试主备库连接」；两库成功后点击「立即同步」，查看完成报告及冲突提示。

连接保存无需重启，不会修改登录密码。空白输入框表示保留原配置，清除备库须明确勾选。测试连接不会上传数据；导入连接文件也不会覆盖文章。
