# Android 本地站点启动故障修复

## 症状与原因

手机导入数据后显示“本地站点未能启动”。当前启动脚本调用 `service.server.once()`，但项目使用的 Astro Node adapter 返回的 `service.server` 是包装对象，真正的 HTTP 服务器为 `service.server.server`。该调用会抛出 TypeError，无法写入 `runtime-ready`；即使端口已经监听，Android 页面也不会打开站点。

这是源码中已确认的启动缺陷。当前未连接用户手机，不能将它视为手机上唯一可能的失败原因。

## 修复计划

1. 从正确的 HTTP 服务器监听启动完成；兼容服务器已经监听的状态。启动失败时删除就绪标记，不将失败服务视为正常。
2. 保存不含配置、口令和正文的启动阶段及错误类型/代码，失败界面支持复制这些诊断信息。首次资源解压与服务启动分别计时。
3. 保持应用 ID 和签名密钥，升级 versionCode 为 2、versionName 为 1.0.2。构建新版 APK，不重新导出或覆盖用户数据。
4. 检查构建与签名结果，在使用说明中明确覆盖安装和真机确认范围。

## 数据与升级

直接安装新版 APK 覆盖旧版，保留应用私有目录中的配置、数据库、媒体缓存和登录数据。不要卸载旧版，不需要再次导入迁移包。启动标记与诊断文件可以更新，个人数据不能删除。
