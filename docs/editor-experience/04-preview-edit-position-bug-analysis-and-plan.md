# 预览与编辑模式位置一致性：根因分析与修复计划

日期：2026-09-27  
范围：文档文章页预览模式与原地编辑模式之间的视口位置保持。本文只记录调查结论和实施方案，不包含代码修改。

## 目标与验收定义

模式切换前，用户正在看的同一段内容应在切换后保持在相同的屏幕位置。该规则适用于两个方向：

1. 预览 → 编辑：异步取文、编辑器挂载和布局交换完成后，视口仍对着点击编辑前正在阅读的内容。
2. 编辑 → 预览：若保存需要等待，保存结束并真正关闭编辑器时，应保留届时用户正在看的内容；不能退回进入编辑时的位置。
3. 用户已经开始手动滚动后，任何延迟定位都不得再抢回视口。

验证以“同一语义内容块的视口 `top` 坐标变化不超过 3 CSS px”为主指标。浏览器滚动范围夹位或内容自身被编辑时允许存在边界差异，但页面滚动和编辑器内部滚动不得各自重复补偿，1 秒稳定期后不得再出现程序性滚动。

## 根因结论

### 已从代码确认的缺陷

**短文档退出编辑时，代码明确恢复到进入编辑前保存的 `window.scrollY`。** `closeEditor()` 的短文分支调用 `instantScrollTo(savedScrollY.current)`（[DocInlineEditor.tsx:443](../../src/components/doc/DocInlineEditor.tsx#L443)，具体分支在 479–483 行）。`savedScrollY` 在 `openEditor()` 点击开始时记录（[DocInlineEditor.tsx:681](../../src/components/doc/DocInlineEditor.tsx#L681)，694 行）。如果用户在编辑期间向下滚动，关闭时此值已经过期，所以会回到旧位置。这与“退出编辑保持当前编辑位置”直接冲突，是确定可复现的代码级 bug。

### 造成位置看起来不稳定的高概率时序问题

**进入编辑使用过早捕获的快照。** `openEditor()` 在请求正文之前捕获页面位置、正文顶部和阅读锚点（694–709 行），随后可能等待正文 fetch（718–725 行）、React 状态更新和编辑器挂载，最后才由 `revealEditor()` 在 `requestAnimationFrame` 中交换 DOM（[DocInlineEditor.tsx:646](../../src/components/doc/DocInlineEditor.tsx#L646)）。等待期间若用户滚动，定位仍使用点击时的快照，因此编辑器显示时可能把用户带回旧位置。预取命中会缩短这个窗口，网络较慢时窗口变大，因而表现像随机。

**切换中存在多个定位者和多次校正。** `revealEditor()` 一帧里执行两轮页面滚动/编辑器锚点应用（659–673 行）。退出时先按锚点恢复，再可能因保存过而异步替换预览 HTML，随后同一锚点再次恢复，并在 300/900ms 调度稳定期校正（[DocInlineEditor.tsx:352](../../src/components/doc/DocInlineEditor.tsx#L352)、385–388 行；[DocInlineEditor.tsx:171](../../src/components/doc/DocInlineEditor.tsx#L171)）。图片、公式等内容高度回流时确实需要处理布局漂移，但多次纠正使最终落点依赖渲染和网络时序。延迟校正目前只监听 `wheel`、`touchstart`、`keydown`，其它滚动来源（例如滚动条拖动）不一定能取消它。

**锚点覆盖不完整时会退到高度比例。** 预览侧锚点以 h2–h4 标题序号及标题的视口偏移表达（[DocInlineEditor.tsx:121](../../src/components/doc/DocInlineEditor.tsx#L121)）。长文中无可用标题、标题被删/改序或视口位于第一标题前时，会回退到编辑器滚动比例映射（退出分支 481–483 行）。源码编辑器与排版后的 HTML 高度差异很大，比例并不能保证同一段内容落在原位。文章有表格、公式、图片、代码块时差距尤其可能随异步布局改变。

**长文定位跨越两个独立滚动坐标系。** 页面滚动定位正文容器，CodeMirror 内部滚动定位编辑内容。`applyAnchor()` 先尝试标题锚点，不命中时以 `scrollHeight * savedProgress` 回退（[DocInlineEditor.tsx:629](../../src/components/doc/DocInlineEditor.tsx#L629)）。CodeMirror 再通过 `lineBlockAt()` 的高度图逐帧修正标题位置（[MarkdownEditor.tsx:483](../../src/components/admin/MarkdownEditor.tsx#L483)、502–523 行）。两套估算/修正分别有效，但调用顺序、容器顶部偏移或内容高度变化不一致时会产生往返偏差。

### 放大因素与证据边界

文章正文启用了 `content-visibility: auto` 和估算 intrinsic size，定位时又临时切换强制布局态（[doc/[id].astro:424](../../src/pages/doc/%5Bid%5D.astro#L424)、431–444 行）。这有利于长文渲染性能，但首次布局高度可能从估算值变为实际值。全局 `scroll-behavior: smooth` 在 [global.css:148](../../src/styles/global.css#L148)，共享滚动工具使用 `behavior: 'instant'` 以规避动画（[doc-viewport.ts:13](../../src/lib/doc-viewport.ts#L13)）；因此主要问题不是单次定位被平滑滚动，而是不同时间点的多次瞬时定位与布局变化叠加。

以上是静态代码证据和机制分析。当前没有浏览器运行时的逐帧滚动轨迹，因此“异步布局回流、多次修正分别贡献多少偏移”仍需在修复前用复现场景和日志确认；不把推断写成已测量的运行时结论。短文档退出回旧滚动值则无需等待运行时确认，源代码已能证明。

## 建议方案

### 统一“当前视口锚点”

把视口位置表达为“当前实际可见的语义内容块 + 该块相对视口顶部的偏移”，而不是进入模式时的页面 `scrollY`、标题序号快照或整篇高度百分比。锚点应覆盖标题、段落、列表、引用、表格、代码块及图片/公式等块级内容；Markdown 源码侧通过解析树的节点范围/源码位置找到对应块，预览侧通过相同源码范围或稳定块标识找到渲染节点。渲染器暂时无法给所有块提供稳定标识时，先使用最近可映射的块锚点并保留像素位置兜底，但兜底只能用于映射失败，不能作为常规比例定位。

### 在真正交换视图的时刻捕获、恢复一次

- 进入编辑：编辑器准备期间保留预览 DOM；紧邻可见 DOM 交换之前重新捕获当时视口锚点。若允许用户在加载期间继续阅读，就以交换前位置为准；如果产品明确要求以点击时为准，则应在等待期间禁止滚动并提供清晰反馈，不能悄悄使用过期快照。
- 退出编辑：等待保存完成后、隐藏编辑器前，重新读取用户此刻的锚点（包括 CodeMirror 当前可见源码块及屏幕偏移）。然后恢复预览并映射到同一内容块。不要复用进入编辑时的 `savedScrollY`。
- 保存后刷新 HTML：将它视作同一次退出事务。先取得最新预览 DOM，再执行一次锚点恢复；若图片/公式回流需要二次布局处理，应只针对同一锚点做受控补偿，并在任何用户滚动输入或滚动条拖动时立即取消。

### 让滚动所有权单一、修正有边界

每次切换确定唯一的主滚动容器：短文通常由页面滚动承载，长文由编辑器内部滚动承载、页面负责正文容器的屏幕坐标。实现一个共享的 capture/restore 流程，页面 `scrollY` 只用于保留正文容器的视口位置，不再同时承担内容锚点定位。删除重复的同帧滚动/锚点应用，比例回退不作为常规路径。每次切换最多一次同步恢复，加上至多一次明确受控的布局稳定校正；校正期间用滚动事件与真实输入事件区分浏览器布局变化和用户主动滚动，并且绝不覆盖用户的新位置。

## 复现与验证矩阵

| 场景 | 操作 | 当前实现预期风险 | 修复验收 |
|---|---|---|---|
| 短文退出 | 页面滚到中段，进入编辑，再在编辑态滚到另一处后退出 | 退出回到进入编辑前的 `savedScrollY` | 预览显示编辑态当前语义块，偏移 ≤3px |
| 长文进入延迟 | 禁用缓存/限速网络，点击编辑后等待时继续滚动，再让编辑器显示 | 使用请求前捕获的旧锚点跳回 | 编辑器显示交换前最后阅读的块 |
| 长文无标题 | 视口位于首标题前或正文无 h2–h4，切换两种模式 | 比例映射偏离 | 可见段落/块锚点仍一致 |
| 保存后退出 | 编辑公式、表格、代码块或图片附近内容，保存并退出 | HTML 替换及图片/公式回流触发再次校正 | 保存完成后同一内容块仍在原视口位置 |
| 退出等待保存 | 内容改动后点退出，在保存期间滚动到另一段 | 锚点若保存前捕获则过期 | 以保存完成、关闭前用户最后位置为准 |
| 人工滚动与延迟校正 | 切换后在 300/900ms 内拖滚动条或触控板滚动 | 现有取消事件未覆盖拖动等输入 | 用户新位置立即胜出，不再被程序拉回 |
| 边界位置 | 页面顶部/底部、窄屏、短文和长文断点附近 | 页面高度夹位、容器切换造成差异 | 不出现可见跳跃；顶部/底部钳位结果稳定 |

## 后续实施计划

1. **建立可复现基线。** 使用一篇覆盖标题、长段落、表格、引用、图片、数学公式和代码块的长文，以及短文/无标题文章。记录进入点击、请求完成、编辑器挂载、视图交换、退出点击、保存完成、DOM 替换和 300/900ms 后的 `window.scrollY`、正文/编辑器容器矩形、内部 `scrollTop`、锚点块及其 `getBoundingClientRect().top`。同时录像或用浏览器自动化记录真实复现。确认短文退出回跳，并量化其它路径。
2. **先修确定性缺陷。** 移除退出短文分支对进入时 `savedScrollY` 的恢复，改为退出时采集当下锚点并按统一流程恢复。确认保存等待结束后的捕获时机。
3. **收敛进入编辑时序。** 保留异步加载，但将锚点捕获移动到真正交换视图之前；校准页面滚动与 CodeMirror 内部滚动的职责，清理重复的同帧定位调用。
4. **扩展锚点映射并收紧回退。** 为非标题块建立源码与渲染块的稳定对应；保留标题锚点作为兼容/优先锚点，移除常规高度比例映射。确保内容被用户编辑或锚点所在块被删除时有可预测的最近块回退。
5. **限制布局稳定校正。** 测量含图片、公式等异步内容的真实回流需求，最多保留必要的一次修正；覆盖滚轮、触摸、键盘、滚动条拖动等用户滚动输入的取消路径。程序校正不得在切换后持续争夺滚动所有权。
6. **自动化回归与验收。** 为短/长文章两方向、无标题、保存等待、异步高度变化和用户干预增加浏览器测试。通过前述 3px 锚点偏移指标，确认切换后 1 秒内没有未授权滚动；同时验证目录跳转仍按用户选择标题定位，不受“保持当前位置”规则误伤。

## 模型选择与额度建议

此问题限定在少数视口/编辑器组件，主要难点是理解浏览器布局时序、双滚动容器坐标和异步渲染的竞态，不需要从头重构编辑器。建议后续实现主模型用 **GPT-6 Sol，medium**：官方模型指南把 Sol 定位为适合日常编码、工作流和需要判断的任务；medium 是该类任务的推荐推理级别。把任务限定为本文件提到的定位链与测试场景，先复现并一次性采集诊断日志，再实施，避免反复让模型重读全仓库。

若第一次实现后仍有难以解释的浏览器布局竞态，可只在审查最终补丁/解释日志时升到 **GPT-6 Sol，xhigh**；不建议全程使用高推理级别。纯文档整理或简单测试调整可用 **GPT-6 Luna，low/medium**。模型名称和 Codex 中可用选项会随账户/产品配置变化；API 价格不能直接换算为 Codex 额度，实际选择以 Codex 模型菜单及账户用量页面为准。

## 实施与浏览器验证（2026-09-27）

后续开发通过真实长文复现确认了另一项关键根因：CodeMirror 初次挂载时语法树只解析了开头，约 5.9 万字符的文章此时仅索引到 3 个标题。切换目标是第 9 个 h2，索引返回空，代码于是走整篇高度比例回退，导致进入和退出都跳到其它小节。修复在模式切换定位时补齐完整语法树，并使用已渲染标题行的实际 DOM 坐标校正高度图估算。退出编辑时还会优先选择距视口顶最近的标题；若下一标题已经进入视口，就不会使用几千像素之外的上一标题作为锚点。

短文退出改为使用保存完成后的当前页面位置。进入编辑在真正交换视图前重新测量；异步刷新预览在替换 HTML 前再次测量，避免使用过时的点击目录位置或退出时快照。编辑态隐藏窗口最右侧原生滚动条，仍保留鼠标滚轮滚动；隐藏时保留原滚动条占用的布局宽度，减少换行抖动。

验证使用本地数据库快照，不改动正式数据。长文标题在预览/编辑切换后的视口偏移由约 1363px 误差降到约 0.1px；编辑中滚轮移动到另一标题再退出，标题偏移差约 0.4px。短文在编辑期间滚动后退出，页面保持退出时的滚动位置。旧浏览器脚本的 20 项断言中，19 项通过；唯一未通过项是“点击同一 tick 内显示加载反馈”，与本次视口定位无关。`astro check` 为 0 错误，全部 782 项单测通过。尚未为所有无标题文档与复杂 MDX 语法建立源码块级映射；这些场景仍使用已有比例兜底，应作为下一轮专项验收对象。
