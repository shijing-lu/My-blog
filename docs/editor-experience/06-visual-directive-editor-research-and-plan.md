# 文档文章编辑：选项卡、画廊、折叠面板可视编辑计划

日期：2026-09-28  
需求来源：文档文章就地编辑时，这三类扩展语法要像现有表格和两／三栏一样显示为接近阅读页的结构，同时允许直接修改。

## 1. 产品定义

作者应在编辑器中直接看见选项卡导航与当前面板、图片网格缩略图、折叠面板标题与展开正文。鼠标点击相应区域即可编辑文字、图片地址或结构参数；右键菜单插入这些语法后立即进入可视编辑。高级情形保留“查看源码／恢复视图”，源码依旧是唯一保存格式。

“接近阅读页”指沿用 `.md-tabs`、`.md-grid`、`.md-collapse` 的视觉规则和响应式尺寸；编辑控件使用轻量悬浮操作条，不把源码定界符直接显示在正常视图。它不要求在编辑器内真正打开图片灯箱，也不要求选项卡跨文章同步状态；这两种行为属于阅读页脚本。

| 类型 | 阅读态外观 | 编辑态直接操作 | 源码格式 |
|---|---|---|---|
| 选项卡组 | 横向标签、当前标签面板 | 点击切换、改标签、增删/移动标签、编辑面板内完整 Markdown、设置初始活动项与稳定 ID | `:::tabs[#id]` + `@tab[:active] 标签` + 正文 + `:::` |
| 图片画廊 | 1–6 列网格、固定比例、cover/contain 图片 | 看缩略图、增删/移动图片、改 alt/地址/图注、改列数/比例/填充方式 | `:::grid columns=N aspect=W/H fit=…` + Markdown 图片 + `:::` |
| 折叠面板 | `<details>/<summary>` 同款标题与正文 | 点击展开、改标题、增删/移动面板、编辑正文内完整 Markdown、调整 accordion/expand 和单项默认态 | `:::collapse [accordion] [expand]` + 无序列表项 + `:::` |

默认“直接编辑”应是点击可编辑区域后出现光标，无须主动切到源码。预览与编辑可共享同一视觉容器：标题处输入框、正文处轻量 CodeMirror 子编辑器、图片处地址/alt 小表单；失焦后仍显示成品结构。所有编辑立刻经主编辑器事务回写 Markdown，沿用文档文章的 1.5 秒自动保存和撤销历史。

## 2. 技术现状与难度

服务端 `renderMdx()` 已支持三种语法，阅读组件分别在 `src/components/mdx/Tabs.tsx`、`Grid.tsx`、`Collapse.tsx`。源码规范化并不简单：`normalizeTabs()` 在解析前把 `@tab` 分区转为列表；`normalizeGridParams()` 编码 grid 参数；`normalizeCollapseParams()` 处理 accordion/expand。它们必须保持原格式可往返，不能把服务端规范化后的内部哨兵写回数据库。

CodeMirror 现有表格是 block `WidgetType`，多栏是跨行 `Decoration.replace` + 每栏子 CodeMirror。三种新语法都跨多行，应沿用 **StateField 直接提供 block replacement**，与表格/数学/代码/多栏装饰范围协调。CodeMirror 官方文档规定跨行替换须由直接 decoration 提供；`WidgetType.updateDOM` 可复用 DOM，`destroy` 清理内部编辑器。[CodeMirror Decoration](https://codemirror.net/examples/decoration/)｜[API Reference](https://codemirror.net/docs/ref/)

难度分布：画廊中等（图片项较结构化），选项卡中高（分区与活动态），折叠面板高（列表缩进、完整块级 Markdown、单项标记）。最大数据风险是把不认识的源码行、手写属性、嵌套内容或未闭合块误当作可视结构后又重写，从而丢字。`remark-directive` 负责阅读管线，允许应用自定义容器，但不为编辑器提供稳定的源码片段往返；需要独立的保守扫描器。[remark-directive 官方仓库](https://github.com/remarkjs/remark-directive)

## 3. 架构方案

1. 新建轻量纯函数扫描器，识别每类**完整、可无损往返**的块，返回外层范围、参数与子项源码范围。扫描时跳过代码围栏和更深一层容器；不支持的结构保持普通源码可编辑。
2. 新建三个专用 Widget，注册到共用 `MarkdownEditor` 的 WYSIWYG decoration StateField。互斥占位：主 WYSIWYG 扫描器先把三类区块行标为 blocked，避免表格、代码、图片、行内高亮装饰落入 replacement 范围；多栏外层仍由现有 columns Widget 管理，其子编辑器里可装入轻量的这些 Widget（需要防止递归）。
3. Widget 内保存一个展示控制器，面板正文复用轻量 CodeMirror；图片采用缩略图 + 内联表单。块外层 CSS 复用阅读类名，编辑控件补 `.cm-*` 类；浏览宽度不足时标签滚动、图片列数自适应、面板内容不横向溢出。
4. 操作命令改源文时只替换对应块，单次事务保存；焦点、活动 tab、展开态及文本选择通过位置映射恢复。结构变更（增删/移动）一次撤销。移除非空 tab/面板时必须明确合并保留内容，或只在空项时允许删除。
5. UI 提供“查看源码/恢复视图”兜底。格式不完整或扫描器无法证明可往返时**不创建 Widget**，直接显示原源码；作者修好语法后自动恢复可视视图。
6. 若右键菜单在这些 Widget 内打开，命令使用当前子编辑器作为 target；图像控件与标签编辑各有自己的上下文，不能误把新结构插入表格单元格或标签名中。

## 4. 关键边界

- 标签/面板正文可有段落、列表、代码、表格、公式、图片。避免把正文降成 `textContent` 后再写回；否则 Markdown 结构必丢。
- 图片画廊参数：列数 1–6；比例允许正整数宽高比，菜单提供常用比值与自定义输入；cover/contain 两种模式。画廊里若有非图片正文，退回源码而不丢弃该内容。
- tabs 至少两项；`@tab:active` 可以指定初始项；可选 stable ID 会联动阅读态同 ID 组。编辑时切换当前项只是预览操作，只有点“设为默认”才改 `@tab:active`。
- collapse 的 `accordion` 与 `expand` 是独立组参数，面板的 `:+`／`:-` 是单项覆盖；编辑时临时展开不改变保存的默认状态。
- 外层可能出现手写代码围栏、冒号、嵌套语法。生成时使用足够长的容器围栏，避免内部 `:::` 提前闭合。扫描器不能识别的输入保留源码，绝不静默截断。
- 图片 URL 可能是相对路径、应用内图片 API、外链；预览失败给占位图，原 URL 保留。灯箱属于阅读态，编辑点击应优先选择图片项而非打开灯箱。
- 当前文档有已有便携目录 `release/portable`，功能完成后按项目既有构建流程原位覆盖。

## 5. 开发顺序与验收

| 阶段 | 工作 | 完成标准 |
|---|---|---|
| A | 保守扫描器与序列化器；确定可视化白名单和源码回退行为 | 正常和错误输入均无文字丢失；源码→结构→源码往返语义一致 |
| B | 画廊 Widget：读图、改参数、增删移动图片 | 网格接近阅读页；图片数据可直接修改并保存；URL 失败保留原值 |
| C | 选项卡 Widget：导航、标题、活动态、正文子编辑器 | 标签与正文均可点选编辑；切换与默认项语义分离；增删移动可撤销 |
| D | 折叠面板 Widget：标题、展开、正文、组/项参数 | 预览的展开与源码默认态分离；正文完整 Markdown 可编辑；缩进合法 |
| E | 与右键菜单、多栏、表格、文档自动保存整合；窄屏/键盘/IME/长文检查 | 新插入立即可视；切换文章无未保存丢失；三类无重叠装饰；便携版原位覆盖 |

建议先完成右键菜单的基础插入与命令路由，再分 B–D 独立实现；这样每种 Widget 的编辑链路可单独检查。各阶段验证包括手写既有源码、菜单新建、修改、撤销/重做、保存后阅读呈现、源码切换和失效回退。

## 6. 模型与额度

主开发可继续使用 **GPT-6 Sol medium**：模板/扫描器、Widget 与样式可按阶段分解。完成 B–D 后若出现跨 Widget 焦点、事务历史或未知源码无损往返的疑难问题，用 **GPT-6 Astra medium/high** 做一次定向设计审查和修复，再回到 Sol。项目中的实例、现有 parser 和失败输入样例比整仓上下文更有用，按文件和复现步骤提供能降低额度消耗。模型选择依据仍为 [OpenAI 官方模型选择](https://developers.openai.com/api/docs/guides/model-selection)；实际 Codex 额度取决于产品套餐，不能按 API 定价折算。
