# 文档编辑首次显示源码：根因调查与修复计划

日期：2026-09-28

## 用户可见现象

文章第一次进入编辑模式时，完整的 `:::tabs`、`:::collapse` 显示为源码；退出到阅读模式后再次进入，才出现可视化编辑。`:::collapse expand` 示例已用当前扫描器直接检查，能够产出完整的 `VisualBlock`，所以该示例的语法并非回退原因。

## 已确认的代码路径

1. `DocInlineEditor.openEditor()` 先把文章源码写入 React state，再在不可见的绝对定位容器中挂载 `MarkdownEditor`；`revealEditor()` 接到 `onReady` 后才在下一帧交换阅读正文和编辑器。
2. `MarkdownEditor` 初始创建时给 WYSIWYG compartment 一个空扩展 `[]`。此时编辑器确实会显示原始 Markdown。
3. 之后才动态 `import('./cm-wysiwyg')`，并一次性安装 WYSIWYG、三类可视指令和分栏扩展。
4. 动态加载失败的 `catch` 目前也调用 `onReady`，因此会把“未安装任何可视扩展的源码编辑器”作为正常编辑态展示。这个失败路径没有用户可见诊断。
5. 容器从 `visibility:hidden`/绝对定位切换到真实位置后，当前代码没有要求 CodeMirror 再测量和刷新视口。跨行块 Widget 对视口与几何状态敏感，首次挂载的布局时序也需纳入修复。

## 根因结论与边界

**确定的缺陷**是首次加载流程允许空装饰编辑器通过“就绪”门槛，且在隐藏布局下完成扩展安装后不做显式几何刷新。这两点都能使首次编辑显示源码，与用户报告的“再次进入后正常”相符。当前没有运行时错误日志或首次加载网络记录，不能断言每次复现一定由动态导入失败还是首次几何测量触发；修复覆盖两个路径，并让后续错误可观测。

## 修复计划

1. 把 WYSIWYG 模块加载提前到创建编辑器之前；文档文章编辑模式只有在可视扩展已准备好后才创建 `EditorState`，避免空装饰首帧。
2. 将三种指令 Widget 与 WYSIWYG 扩展作为同一次初始配置装入；`onReady` 仅在扩展已装入、视图完成测量后发出。加载失败显示明确错误和重试入口，不能静默降级为源码并称作完成。
3. 阅读态→编辑态交换后调用 CodeMirror 的 `requestMeasure()` 并在可见布局中完成一次视口刷新；不要靠退出再进入触发修复。
4. 保留显式“查看源码”与“恢复扩展视图”操作。默认首次进入始终为可视模式，除非块本身不满足保守扫描器规则。
5. 核对首次打开、再次打开、长文内滚、短文自适应、选项卡和折叠面板、表格/分栏同页出现等路径；失败时保留源码且显示原因，不修改文章内容。

## 验收

打开含选项卡和折叠面板的文章，第一次点编辑即可看到结构化可编辑组件；中间无源码闪现。重进、切文章和从右键新建后行为一致。完整但不被扫描器支持的手写语法可退回源码，并明确说明这是该块的语法回退。
