# 文档文章编辑：Markdown 右键菜单调研与开发计划

日期：2026-09-28  
状态：需求梳理与方案；本文件不包含本功能的实现。

## 1. 目标和范围

在文档文章的就地编辑模式中，鼠标右键或键盘菜单键打开贴近 Obsidian 的上下文菜单。菜单根据“当前是光标还是选区”提供相关命令；按悬停／键盘展开类别，再选择具体格式。指令插入后直接落到原 Markdown 光标／选区位置，由现有自动保存链路保存。

首期入口限定为文档详情页 `DocInlineEditor` 使用的 ghost 编辑模式。`MarkdownEditor` 同时用于后台写作台、快速编辑和多栏子编辑器；必须由显式属性启用，不能不加选择地改变所有编辑器的右键行为。原生复制、剪切、粘贴、全选、链接等菜单入口应继续可用。

本功能使用项目已支持的 Markdown/MDX，不代表承诺 Obsidian 的所有语法或编辑行为。

## 2. 现有代码核实

文档文章按需加载 Markdown 原文，在正文位置挂载共享的 CodeMirror 6 `MarkdownEditor`，启用 `wysiwyg` 和 `variant="ghost"`。ghost 模式不显示完整格式工具栏；文档编辑自动保存仍由 `DocInlineEditor` 负责。

| 能力 | 项目当前源码／规则 | 菜单方案的含义 |
|---|---|---|
| 普通引用 | Markdown `>`；编辑器已有行前缀命令 | 与 Callout 分开列，避免把任意引用都改为有颜色的 Callout |
| Callout | `> [!type] 标题`；支持折叠前缀；`src/lib/mdx/callout.ts` 定义 11 种规范类型 | 第三级只列已有的 11 种：note、info、tip、success、question、warning、failure、danger、bug、example、quote |
| 容器提示框 | `:::note` 等由 `ADMONITION_TYPES` 处理，目前为 note、tip、warning、danger、info | 与 Obsidian Callout `> [!type]` 语法不是同一实现。首期不把它们重复加进 Callout 菜单；若用户明确需要，之后另建“提示容器”类别 |
| 表格 | GFM 管线；`cm-table.ts` 已提供可视化单元格、行列操作与表格菜单 | 右键插入走现有表格扩展；不再造一套表格编辑器 |
| 图片画廊 | `:::grid`；列数 1–6，比例为正整数宽高比，适配模式 cover/contain；默认 3 列、16:10、cover | 画廊格式实际上是“列数 × 比例 × 填充”，比例可自定义，不能假装只有几个固定皮肤 |
| 选项卡组 | `:::tabs` + 多个 `@tab`；标签可有 Markdown，可指定首选标签和稳定 ID；相同 ID 的组可同步 | 项目没有多种卡片皮肤。“类型”应呈现两项／三项等结构模板，以及独立／同步行为；标签名由作者输入 |
| 折叠面板组 | `:::collapse` 内必须是一个顶层无序列表，每个列表项对应一个面板；支持 accordion、expand、单项 `:+` / `:-` | 提供默认折叠、默认展开、互斥折叠、互斥且默认展开四种已有参数组合，并生成合法的 starter panel |
| 荧光高亮 | `==文字==`，五个规范变体 primary、secondary、tertiary、error、tip；已有语义别名 | 有选区时第三层按五种规范变体显示，名称用中文；点击只包裹所选文字并使用规范源码 |
| 黑幕 | 行内扩展 `:spoiler[文字]`，由 `remarkSpoiler` 渲染 | 对选区执行行内包裹；不混进块级容器分类 |
| 粗体／斜体／删除线 | `**文字**`、`*文字*`、`~~文字~~`；已有快捷命令 | 复用 `wrapSelection`／现有命令，保持一个撤销步骤 |
| 下划线 | 当前命令与 WYSIWYG 规则未发现统一的下划线语法 | 实施阶段先确定输出规范；建议采用受控的 `<u>文字</u>`，并验证 MDX 阅读端、编辑预览、源码转义一致后再开放菜单 |

主要入口为 `src/components/doc/DocInlineEditor.tsx` 与 `src/components/admin/MarkdownEditor.tsx`。Markdown 操作已有 `insertBlock`、`wrapSelection`、`toggleLinePrefix`，编辑器实例通过 CodeMirror 事件扩展管理；WYSIWYG 由 `cm-wysiwyg.ts` 按需装入，块替换装饰也集中在那里。最终阅读语义在 `src/lib/mdx.ts`、`src/lib/mdx-plugins.ts`、`src/lib/mdx/*` 和 MDX 组件注册表中定义。

## 3. 菜单关系：块结构和行内格式分开

菜单显示的一级标签沿用截图习惯“段落设置”。其内部必须分清两种互斥上下文：

```text
右键位置
├─ 无选区：创建块级结构（在光标处分割/插入）
│  └─ 段落设置
│     ├─ 普通引用                         → Markdown >
│     ├─ Callout 引用 ▸                  → 11 种 [!type]，可选折叠状态
│     ├─ 表格                             → 默认表格，复用现有 TableWidget
│     ├─ 图片画廊 ▸                       → 列数/宽高比/图片适配参数选择器
│     ├─ 选项卡组 ▸                       → 两项/三项 starter；独立或稳定 ID 同步
│     └─ 折叠面板 ▸                       → 4 种已支持的组行为组合
└─ 有选区：格式化当前所选文字（行内）
   └─ 段落设置
      ├─ 荧光高亮 ▸                      → 主色/次色/第三色/错误/提示
      ├─ 黑幕                             → :spoiler[选中文字]
      ├─ 加粗                             → **选中文字**
      ├─ 斜体                             → *选中文字*
      ├─ 下划线                           → 采用确认后的下划线语法
      └─ 删除线                           → ~~选中文字~~
```

荧光高亮只出现一次，变体在第三级中选择；不另放一个行为重复的“高亮”直达项。普通引用不是 Callout；Callout 只接受其 11 个规范类型。图片画廊是一组布局参数，不是 `Grid` 组件的多种外观。选项卡标签内容由用户定制，菜单不能硬编码“npm／pnpm”一类业务标签。折叠面板标题和正文是用户数据，不是面板类型。

### 3.1 无选区的实际菜单

顶层保留截图中已有的常用编辑菜单，例如链接、文本格式、段落设置、插入、剪切／复制／粘贴、纯文本粘贴、全选、查找。首期在“段落设置”放入上图中的块级选项。Callout、画廊、选项卡组、折叠面板类别有右侧箭头和第三级；表格可先直接插入项目默认 2 列含表头模板，再由现有表格 Widget 调整结构。

右键发生在有内容的段落中时，块插入应拆开当前段落，并保留左右两侧文字；不得拿光标所在整行当选区，也不得覆盖邻接块。空行位置直接插入。代码围栏、表格单元格等不能容纳块级结构的位置，要把块插到所属结构之外，或禁用不合法命令并解释原因。

### 3.2 有选区的实际菜单

打开菜单时冻结原始选区；菜单按钮取得焦点后仍将命令应用于打开菜单前选中的原文。右键不应悄悄把选区换成鼠标所在词。黑幕、粗斜体、荧光高亮、下划线、删除线仅作用于选区，不修改段落结构。多段选择在整个跨度统一包裹或明确禁用；首期建议统一包裹，遇到跨块的非法边界时保守禁用并保留选区。

## 4. 第三级选择内容建议

| 二级项 | 第三级的内容 | 依据与实现规则 |
|---|---|---|
| Callout 引用 | 11 个 Callout 规范类型；分隔线之后可选普通／默认展开／默认折叠 | 规范类型来自 `CALLOUT_TYPES`；语法写为 `> [!type]`。折叠状态必须服从现有解析规则 |
| 图片画廊 | 紧凑配置器：列数 1–6；常用比例 16:10、16:9、3:4、1:1 和自定义；适配 cover/contain；实时小预览/当前选择摘要 | 不能把可输入的任意正整数比例穷举成无限菜单项。组合式选择覆盖所有有效格式而不渲染几十个平铺行 |
| 选项卡组 | 两项／三项 starter；独立组／输入或选择稳定 ID 同步组；添加更多标签留在新建后的组内操作 | 项目真实能力由 tab 标签数、active 标记和 stable ID 组成，没有另一套卡片样式类别 |
| 折叠面板 | 默认全部折叠；默认展开；accordion；accordion + expand | 这四项是 `accordion`、`expand` 两个独立布尔参数的全部组合；新建一个标题和正文占位面板 |
| 荧光高亮 | primary、secondary、tertiary、error、tip | 这是项目已渲染的五种规范变体；别名只用于读入兼容，菜单统一写规范名 |

第三级悬浮面板需允许指针从第二级横向移动过去，设置短暂离开延迟；不能因跨菜单缝隙而闪退。鼠标悬停可预览，点击确认；键盘通过方向键/Enter 展开与选择。自定义画廊比例和稳定 ID 可在第三级面板内联输入，避免再加第四级悬浮菜单。

## 5. 技术方案

### 5.1 触发、选区和浮层

1. 给 `MarkdownEditor` 增加显式 `contextMenu` 能力开关，只在文档文章 ghost 编辑器传入。普通写作台及其他调用方保持原行为。
2. 用 `EditorView.domEventHandlers({ contextmenu })` 捕获编辑区域的鼠标右键和键盘上下文菜单事件；对这一区域抑制系统原生菜单。事件能力由 CodeMirror 官方事件扩展提供。
3. 鼠标右键 + 有非空选区：快照当前 `EditorSelection`，菜单锚在指针附近，但动作严格使用快照选区。没有选区：由 `posAtCoords` 取得光标位置。键盘菜单键 / Shift+F10 使用当前光标位置。
4. 使用单独的菜单浮层组件渲染三级面板；基于指针坐标定位，贴近光标；视口边缘自动向左/向上翻转。浮层不要直接篡改 CodeMirror content DOM，也不要修改正文 React 渲染树。
5. 菜单执行前校验原编辑器及选区仍有效。所有成功操作通过单个 CodeMirror transaction 写回 Markdown，复用 `onChange` 自动保存和 undo history；命令完成后关闭浮层并把焦点还给编辑器。
6. 若右键落在分栏子编辑器或其他 Widget 中，命令目标应为实际拥有焦点的 `EditorView`。项目已有 `columnTarget()` 可作路由参考。表格单元格应优先保留 TableWidget 自身的行列菜单，分清“单元格操作”和“在表格外插入新块”。

状态只在右键或选择改变时更新；三级菜单的静态选项表在模块级定义，滚动/键入时不重建整篇 MDX，也不重新挂载主编辑器。portal/浮层在关闭、页面切换、编辑器销毁时清理定时器和焦点监听。

### 5.2 内容写入和边界

- **块插入：** 在空行直接插入；在普通段落中将段落于光标处拆为前文、块、后文。调用项目已有的源码规范化入口生成 grid/tabs/collapse 参数，避免菜单绕过哨兵编码和 remark-directive 的限制。
- **块模板：** Callout、tabs、collapse 插入可编辑的最小合法模板并选中标题占位；gallery 插入至少一个 Markdown 图片占位。表格走现有表格插入/Widget 集成。
- **行内格式：** 保存 `from/to` 选区快照，再精确包裹语法。荧光变体写项目认可的标记形式；spoiler 写 `:spoiler[...]`；下划线先统一源码规范后再开放。
- **链接菜单：** 采用编辑器已有 `wrapSelection` 命令。相对链接、外链、无选区时占位文字行为应沿用既有规则，不另建不兼容解析形式。
- **无损：** 取消菜单不动文档；非法上下文禁用块级项；撤销一次应回退一次插入或包裹；未闭合输入不吞字；自动保存失败仍遵从 `DocInlineEditor` 原有状态反馈。

### 5.3 可访问性和触屏

菜单要有可见焦点、明确的 ARIA 标签与 expanded 状态、Escape 关闭并还焦点。菜单打开后方向键在当前层移动、左右键进出子菜单、Enter 执行；不用 Tab 在菜单项之间移动。触屏没有右键，需要同时提供可见的“更多 Markdown”入口（例如编辑器轻量工具栏按钮）；与同一菜单共用命令目录。

W3C APG 指出上下文菜单可由 Shift+F10 触发，并规定菜单/子菜单的方向键、Enter、Escape 焦点行为；仅加 ARIA role 不会自动获得键盘行为。因此实现需显式实现状态机并做键盘验收。

## 6. 分阶段开发计划

| 阶段 | 内容 | 交付与完成门槛 | 粗估 |
|---|---|---|---:|
| A. 规格与写入样例 | 确认 menu tree、空行/段落中间/列表/代码/表格等光标位置规则；固定每种菜单输出源码；敲定下划线语法 | 规格表含菜单条件、源语法、无效上下文及降级行为；现有 `renderMdx` 能稳定渲染所有模板 | 0.5–1 天 |
| B. 浮层骨架与选区保持 | 编辑器开关、右键/键盘触发、坐标翻转、关闭逻辑、当前选区快照、方向键层级导航 | 光标右键定位正确；选区右键格式化仍命中原选区；点击菜单不会丢失或移动源选区 | 1–2 天 |
| C. 行内格式菜单 | 五色高亮、spoiler、粗体、斜体、下划线、删除线；复用编辑命令和保存链路 | 每项写回预期源码且经文章渲染；undo/redo、中文输入、选区跨行行为正确 | 0.5–1 天 |
| D. 块结构三级菜单 | 普通引用/11 类 Callout、表格、画廊参数配置器、tabs 结构模板、collapse 四类组合 | 每个模板在 caret 位置合法插入；可立即继续编辑；表格复用原 Widget；各现有 syntax 渲染器通过 | 1–2 天 |
| E. 兼容、无障碍和便携交付 | 分栏子编辑器路由、表格菜单共存、窄屏触屏入口、保存状态、回归、文档和固定便携目录构建 | 键鼠均可完成；无保存/选区丢失；文档编辑与写作台旧菜单行为明确；release/portable 覆盖成功 | 1–2 天 |

总估计约 **4–8 人日**，差异主要来自 CodeMirror 装饰光标定位、分栏/表格内部右键路由和块级插入边界。菜单 UI 本身难度中等，保持选区与源 Markdown 数据一致是核心风险。

## 7. 验收矩阵

1. **无选区：** 空段落、普通段落中间、文首/文末；各插入一类块后前后文都保留，光标进入合理占位符。
2. **选区：** 普通词、多行、已有强调/链接内文字；右键菜单打开后 selection 不漂移，分别应用六类行内动作；撤销/重做只跨一步。
3. **真实项目格式：** 11 Callout、表格行列编辑、gallery 全参数、2/3+ tabs 稳定 ID、4 种 collapse；保存后阅读模式正确呈现。
4. **事件：** 鼠标右键、键盘菜单键、Shift+F10、点击外部、滚动、选择改变、快速切换文章、编辑器销毁。
5. **嵌套与冲突：** 围栏代码、列表、普通引用、表格 Widget、图片画廊、现有多栏子编辑器；非法上下文不损坏原内容。
6. **适配：** 视口四角菜单翻转、100%/200% 缩放、窄视口触屏入口、暗色主题、读屏标签、中文输入法。
7. **性能：** 菜单静态目录懒用，不因每个击键加载 MDX 或 React 全文预览；抽查长文菜单弹出和插入响应。

## 8. 模型建议与额度控制

**主开发建议：GPT-6 Sol，medium。** 这项工作主要是已有技术栈中的多文件编码、规则整理、CodeMirror 事务与 UI 状态协调，官方模型选择文档将 Sol 描述为适用于日常编码、研究和需要判断力与完整性的工作。

**按需升级：GPT-6 Astra，medium 或 high，仅用于一次定向审查。** 若开发中出现右键选区漂移、Widget 的 `posAtCoords` 映射、undo/自动保存交错或分栏焦点回归，再让 Astra 针对这些代码和复现步骤做深度审查。不必整个开发流程固定使用最高档。

**低额度执行：** 先用 Sol 完成本文件阶段 A–D；一次只给当前阶段文件和具体验收样例；避免每一轮重复贴整仓；每个功能组完成后跑定向检查，最终跑浏览器矩阵；只在最终复杂编辑器边界审查调用 Astra。模型官方资料建议用代表性任务对比模型和推理强度，保留满足质量门槛的较轻设置；Codex 订阅额度与 API token 价格不是同一计量方式，因此这里不虚构额度或美元折算。

OpenAI 官方模型选择：[Model selection](https://developers.openai.com/api/docs/guides/model-selection)。

## 9. 调研来源

- 用户提供的 Obsidian 右键菜单截图：参考其悬浮分层和菜单密度；不复制其内部实现。
- [CodeMirror 6 Reference Manual：DOM event handlers](https://codemirror.net/docs/ref/#view.EditorView^domEventHandlers)：编辑器级 contextmenu 事件接入点。
- [CodeMirror 6 Tooltip example](https://codemirror.net/examples/tooltip/)：浮层可随编辑器位置定位，并通过状态驱动避免 DOM 副作用同步问题。
- [CodeMirror 6 Decoration example](https://codemirror.net/examples/decoration/)：编辑器内容 DOM 应由 CodeMirror 管理，外部 UI 不应直接重写内容节点。
- [W3C WAI-ARIA APG: Menu and Menubar Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/)：上下文菜单触发、子菜单方向键、Enter/Escape 和焦点路径。
- [MDN: `contextmenu` event](https://developer.mozilla.org/en-US/docs/Web/API/Element/contextmenu_event)：鼠标右键、键盘上下文菜单键触发及浏览器默认行为。
