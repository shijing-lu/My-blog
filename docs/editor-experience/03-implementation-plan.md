## 产品验收原则

1. 点击「编辑」后，不滚动播放动画；切换前后同一段落尽量停留在相同屏幕位置。若布局发生必要的单帧校正，用户不应看到持续滚动。
2. 点击立即有明确反馈，但编辑态继续融入阅读正文，不额外弹出一张编辑卡片。
3. Markdown 是唯一持久化数据；所有可视化块的编辑都写回源文本，支持撤销/重做。
4. 先承诺渲染器明确支持的 Markdown 集合，再单项扩展语法；任何失败装饰都退回可编辑源码，不白屏、不吞内容。
5. 表格、引用/Callout、列表等结构块必须有键盘路径，不能只靠鼠标菜单。

## 建议的量化目标（阶段 0 测基线后确认）

- 入口反馈：点击后一个渲染帧内出现清楚的「正在进入编辑」状态。
- 预取命中：不额外等待文章正文请求；首个可编辑焦点时间以本机实测为准，目标不超过 300ms。
- 预览切换：进入与退出无持续滚动动画；同一段落最终视口偏差目标不超过 8 CSS px，切换稳定后不再二次跳位。
- 输入：中等文章打字期间，不因单字符输入触发全 React 岛重绘；大文档统计键入延迟 P95 并与阶段 0 基线比较，不能退化。
- 表格操作：编辑一次表格结构只产生一个可撤销事务；Markdown 再解析后结构和值保持一致。

这些数值是初始验收建议，需结合设备、文档大小和真实基线在阶段 0 后确认；不能用未测量的目标代替性能证据。

## 模型和额度建议

**建议持续开发主力用 GPT-6 Sol，reasoning medium。** 这项工作需要读懂现有编辑器生命周期、滚动坐标、Markdown 装饰和保存安全；官方模型选择说明把 Sol 定位为适合复杂编码的平衡型日常模型。遇到模式切换与 CodeMirror 装饰交错的疑难问题，再临时升到 Sol xhigh 或调用 Astra 做一次深度审查，不要全程用最高档。格式矩阵整理、单个测试补充和文档校订等清晰小任务可用 GPT-6 Luna low/medium。

OpenAI 官方 API 模型目录当前列出的标准文本 token 价格为：Sol 输入/输出每百万 token `$2/$10`，Astra `$10/$50`，Luna `$0.10/$0.50`；这些是 **API 价格，不等于 Codex 桌面订阅的额度扣减规则**。桌面端模型可用性与使用限制依账号计划和应用当前设置而异，应以模型选择器和使用额度面板为准。[模型选择指南](https://developers.openai.com/api/docs/guides/model-selection) [GPT-6 模型目录](https://developers.openai.com/api/docs/models)

降低总额度的执行习惯：按上述阶段小步实施，只把相关文件和测试给模型；先固定交互验收与 Markdown fixture，后续每轮围绕一项行为；测试失败时先读具体失败输出，不重复全量审查；通过关键用例后再做一次集中式集成审查。
