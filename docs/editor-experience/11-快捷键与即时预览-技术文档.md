# Markdown 快捷键与即时预览：技术文档

## 1. 当前实现

`src/lib/editor-shortcut-defs.ts` 定义 16 个命令与默认键位，`src/components/admin/md-keymap.ts` 将这些 ID 映射为 CodeMirror 命令，`src/components/admin/EditorShortcutsSettings.tsx` 录制并展示设置。自定义键位通过 `/api/editor-shortcuts` 存入 `settings`，`MarkdownEditor.tsx` 初始化时装入默认 keymap，异步读取配置后以 `Compartment` 替换。

可视化编辑使用 `cm-wysiwyg.ts`、`cm-preview-cache.ts`，同时接入 `cm-table.ts`、`cm-visual-directives.ts`、`cm-columns.ts`。目前强调、删除线、行内代码、链接和高亮的标记会被隐藏，但部分隐藏装饰没有 `reveal` 范围，导致光标移入后没有完整源码。表格由 `TableWidget` 直接编辑单元格，现有实现刻意不设置整块源码回显；此行为应保留。

## 2. 快捷键设计

### 2.1 命令清单

以稳定命令 ID 为主键建立“定义、执行、设置、验收”单一清单。保留已有粗体、斜体、删除线、行内代码、链接、代码块、六级标题、引用、无序/有序/任务列表。补充项目已有语法所需的插入或切换命令：下划线、高亮、剧透、图片、水平线、表格、脚注引用/定义、行内/块级公式、Callout、提示块、选项卡、折叠面板、图片画廊和多栏。具体模板复用 `markdown-context-templates.ts`、格式目录和现有右键菜单能力，避免同一语法有两套序列化结果。

组合键是否设置默认值由冲突审计决定。语法覆盖不等于所有命令必须抢占默认键位：可把无默认绑定命令放在同一设置列表中供用户录制；服务端应区分“已知命令”和“存在默认绑定”，不能沿用以 `DEFAULT_BINDINGS[id]` 判断命令是否合法的方式。

### 2.2 事件路径与失效排查

逐项核查 `KeyboardEvent` → `bindingFromEvent()` → `normalizeBinding()` → `resolveBindings()` → `buildMdKeymap()` → `MD_COMMANDS[id]` → CodeMirror transaction。检查以下具体风险，再依据复现结果修改：

- `defaultKeymap`、保存/搜索键位与 Markdown keymap 的优先级；同组合键是否先被基础功能接管。
- `Mod`、`Alt`、`Shift` 的录制结果与 CodeMirror 解析结果是否一致；国际键盘上的标点键是否被错误规范化。
- 现有冲突策略在 `buildMdKeymap()` 中跳过后续冲突 ID；设置页、服务端与实际 keymap 对冲突应采用同一规则。
- Web 浏览器保留组合键、Electron 菜单或系统级按键占用、输入法组合、焦点在子编辑器或普通输入框时的事件归属。
- 设置 API 异步返回后当前编辑器是否正确热替换；错误配置或离线场景是否使用可执行的默认键位。

新增命令使用 CodeMirror transaction 修改最小源码范围；复用现有命令和模板生成器。对选区、空光标、多行、重复触发分别约定光标落点与 toggle 语义。表格单元格和指令 Widget 的子编辑器先处理其自身键盘行为，父 keymap 不应截获输入。

## 3. 即时预览设计

### 3.1 语法范围与装饰

为每个预览型语法记录完整源码范围、内容范围、标记范围与装饰项。`cm-preview-cache.ts` 按光标和选区判断装饰回显；行内格式需要让两侧隐藏标记在同一语法范围内同步回显，不能只恢复一侧。边界采用半开区间，并处理光标恰好位于开闭标记两侧的情况。嵌套格式先由更精确的解析结果确定范围；无法安全分层的片段保留源码，以免正则替换产生重叠装饰。

按行为分三类：

| 类别 | 例子 | 激活方式 | 离开后 |
| --- | --- | --- | --- |
| 源码回显 | 强调、下划线、高亮、链接、静态代码/数学、普通引用 | 光标或选区进入对应范围 | 恢复预览 |
| 可视化原地编辑 | 表格、任务复选框、选项卡、折叠、画廊、多栏 | 点击单元格或可见控件 | 保持组件预览 |
| 源码保底 | 未闭合、解析异常、无法无损往返的嵌套 | 直接编辑原文 | 修复合法后再尝试预览 |

图片与脚注引用等含可点击行为的预览项，应把“打开目标”和“编辑源码”分开，避免一次点击既导航又改写。已有指令 Widget 可继续提供显式“查看源码”高级入口；普通点击仍进入可视化编辑。

### 3.2 表格与交互控件

`TableWidget` 保持非 `reveal` 装饰；单元格使用自身的输入和焦点管理，修改后通过主编辑器事务写回 Markdown。与当前 `cm-table.ts` 的结构操作保持同一撤销历史。任务复选框继续将 `[ ]` 与 `[x]` 作为定向改写，不因光标靠近而被替换成整行源码。可视指令和多栏遵循相同的“组件内部直接编辑”规则，只有扫描器无法证明无损往返时才退回源码。

### 3.3 可访问性、性能和数据安全

键盘操作应与鼠标等价：Tab 能进入可视化子控件，Escape 能退出焦点区域，阅读文字时可通过键盘进入源码编辑。缓存装饰按文档对象复用；光标移动只重新计算受影响的预览范围，避免每次都扫描长文。IME 组合输入期间避免销毁正在输入的 DOM 或重建 Widget。任何解析失败都保留原始 Markdown，不以空字符串或截断的结构写回。

## 4. 配置与兼容

沿用 `editor_shortcuts` 设置键与 `/api/editor-shortcuts` GET/PUT 结构。旧配置保持原命令 ID 和绑定；新命令缺少用户配置时按经审计的默认绑定或“未设置”处理。设置保存后新打开的 `MarkdownEditor` 生效；若后续支持即时热更新，应作为单独行为实现并在 UI 上说明。保持设置页当前视觉样式与主题变量。

## 5. 覆盖关系

主编辑器：`MarkdownEditor.tsx`；宿主入口包括 `LiveEditor.tsx`、`DocInlineEditor.tsx`、`DiaryEditor.tsx`、`CalendarDiaryDialog.tsx` 与 `QuickNoteFloat.tsx`。写作台当前启用 `wysiwyg`，仍需单独检查非 `wysiwyg` 的 `cm-live-preview.ts` 路径，避免相同 Markdown 在不同入口出现不同的可见编辑行为。阅读器以 `mdx-plugins.ts` 和语法手册为最终语法基准。

## 6. 交付验证

使用同一组合法与异常 Markdown 样例核对：阅读渲染、编辑预览、源码保存后的再次打开。快捷键对默认与自定义绑定、网页与 Electron、焦点在主编辑器与子控件分别检查。表格尤其验证单元格编辑和结构操作后源码完整、撤销重做稳定；遇到不能安全预览的语法直接显示可编辑源码。
