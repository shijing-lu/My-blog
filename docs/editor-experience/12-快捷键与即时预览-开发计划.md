# Markdown 快捷键与即时预览：开发计划

## 目标与顺序

先修复现有快捷键失效，再补充项目已支持语法的命令和设置项，最后统一即时预览及可视化控件的交互。每个阶段都以真实编辑结果、保存后的 Markdown 和再次打开的显示作为完成条件。

## 阶段 1：语法与快捷键审计

1. 将语法手册、`mdx-plugins.ts`、格式目录、右键菜单和编辑器扩展对齐，列出“语法 → 插入入口 → 预览方式 → 编辑方式 → 是否需要默认键位”的逐项矩阵。包括 GFM、公式、脚注、下划线、高亮、剧透、Callout、提示块、表格、选项卡、折叠、画廊和多栏。
2. 对已有 16 个绑定逐项复现：Windows Electron、普通浏览器、空选区、有选区、修改设置后重开编辑器。记录未生效原因，包括按键占用、键名规范化、冲突与 keymap 优先级。
3. 确认新增命令的默认键位。仅采用没有已知冲突的组合；其他命令显示“未设置”，由用户录制或通过现有菜单插入。

**完成条件**：有可追溯的语法和按键矩阵，所有现有失效键都有明确原因或可复现边界。

## 阶段 2：快捷键命令与设置

1. 调整 `editor-shortcut-defs.ts`、`md-keymap.ts`、`editor-shortcuts.ts`，补齐命令执行、无默认绑定表示、服务端合法 ID 校验、旧配置兼容和冲突规则。
2. 将模板型操作接到项目已有 Markdown 模板生成器；包裹型操作支持选区切换；块级操作处理多行选区和光标落点。不要让快捷键绕开表格或指令组件的自身编辑逻辑。
3. 在 `EditorShortcutsSettings.tsx` 沿用现有分组和控件样式，展示新增命令、未设置状态、录制/恢复默认、浏览器保留键说明与冲突提示。API 响应保持兼容。

**完成条件**：设置中每个命令均对应实际 CodeMirror 命令；保存、重新加载和重开编辑器后能执行；旧自定义键位保留。

## 阶段 3：即时预览与可视化编辑

1. 在 `cm-wysiwyg.ts` 与 `cm-preview-cache.ts` 中为行内格式和静态块统一定义语法范围与回显规则。光标进入时显示完整相关源码，离开后恢复预览；处理嵌套、选区边界、多光标和长文滚动。
2. 保持 `cm-table.ts` 的单元格原地编辑和非源码回显；任务复选框直接切换。核对 `cm-visual-directives.ts` 与 `cm-columns.ts` 的可见编辑入口，防止普通点击切换整块源码。
3. 对未闭合、重叠或无法无损解析的语法显示源码，不进行破坏性规范化。对 `cm-live-preview.ts` 检查同一语法在非可视化模式下的编辑行为。

**完成条件**：普通格式满足“离开预览、进入源码”；表格和其他可视化组件满足“点击后仍在预览中编辑”；保存、撤销与重做保真。

## 阶段 4：入口验收与交付

| 场景 | 验收结果 |
| --- | --- |
| 设置页 | 旧键与新键能录制、保存、检测冲突、恢复默认；无默认键状态清楚 |
| 写作台和文档原位编辑 | 快捷键执行一致；强调、链接、代码等的光标进出行为一致 |
| 日记与随心录 | 同一编辑器行为生效，宿主保存操作不受影响 |
| 表格 | 单元格点击直接编辑、Tab/行列操作可用；不切整块源码；保存和撤销重做保真 |
| 其他可视组件 | 复选框、选项卡、折叠、画廊、多栏保持直接交互 |
| 边界输入 | IME、嵌套、转义、未闭合语法、多光标、长文均可继续编辑且不丢字 |
| 运行环境 | 浏览器保留键提示准确，Electron 键盘行为与预期相符 |

先进行必要的编辑器和配置验证，再根据改动范围决定是否构建。若需要更新便携桌面版，只在 `release/portable` 构建；目录被运行中的桌面程序占用时通知用户退出，确认进程停止后继续。

## 风险与处理

- 新增默认键可能与浏览器、Electron 或已有编辑器命令冲突：默认留空并允许录制，设置页提供说明。
- 靠正则识别复杂嵌套可能产生重叠装饰或删改源码：优先使用稳定解析范围，遇到不确定内容保留源码。
- 可视化子编辑器的焦点和父编辑器快捷键可能互相抢占：为控件确定事件归属，逐入口验收。
- 预览切换可能造成光标或滚动跳位：限制装饰重建范围，并以长文与输入法场景检查。

## 开发模型

建议 **GPT-6 Sol，medium 推理** 完成主开发。此次工作涉及 CodeMirror 装饰、焦点、键盘事件、配置持久化和多个可视化 Widget，需要在跨文件修改中兼顾正确性与额度。OpenAI 官方将 Sol medium 用于需要判断和完整性的日常编码，并将 Sol 定位为智能与成本平衡的选择：[模型选择指南](https://developers.openai.com/api/docs/guides/model-selection)、[GPT-6 Sol](https://developers.openai.com/api/docs/models/gpt-6-sol)。

开发时以具体复现步骤和受影响文件提供上下文；命令标签、文案或独立样例等明确的小任务可以使用 GPT-6 Luna medium。若发现难以定位的跨 Widget 焦点或源码往返问题，再针对该问题提高 Sol 推理档位。这里的模型选择是 Codex 开发模型，与站点自身 AI 设置中的运行时模型无关。
