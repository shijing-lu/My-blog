# 工具链启动门户：需求修订与可行性调研

日期：2026-10-09。状态：方案调研，未实现功能、未启动外部工具、未构建客户端。

## 1. 本次修订

取消博客内嵌工具、博客工具工作区与配套文本处理台开发。工具链变为站主在 Windows 桌面端使用的启动门户，入口仍位于“随心录”右侧。外观继续沿用当前博客的暖白、橙红、黑色描边、硬阴影及首页猫咪。

| 类型 | 添加方式 | 点击后的行为 |
|---|---|---|
| 本机软件 | 选择 .lnk 或 .exe，填写名称、分类、标签 | 交给 Windows 打开软件 |
| 源码项目 | 选择项目目录，AI 辅助识别启动方式，可手动编辑 | 启动独立本地服务，在无标签栏的浏览器应用窗口打开 |
| 网页工具 | 填写名称和 HTTP/HTTPS 地址 | 直接在外部浏览器打开网页；可另提供应用窗口选项 |

用户已确认两项生命周期要求：退出博客时，源码工具继续运行；关闭该工具自己的主应用窗口时，停止它的服务。两者必须分别实现。

## 2. 可行性结论与证据边界

三类入口均可实现。源码项目需要独立后台监管器，负责服务、窗口和日志；当前博客本地服务的监管器不能直接复用其退出策略。

当前已检查：
- desktop/main.cjs:200 在博客退出时停止 localServer。
- desktop/server-process.cjs:35–38 的 stop 直接结束所持子进程。
- desktop/main.cjs:239–245 使用 shell.openExternal 打开外部网页，不能保证打开独立应用窗口或识别关闭。
- desktop/preload.cjs:16 起只有限定能力，尚无工具登记、启动、停止接口。
- desktop/main.cjs:703 全量继承博客环境，不适合传给独立项目。
- src/lib/pi-ai.ts:65–95 已有文字生成方法，支持现有订阅/API 模型，可用于“启动方式分析”的独立任务。
- 本机已找到 Microsoft Edge、Node.js、npm 和 pnpm。发现程序路径不代表所有项目的依赖及版本要求已满足。

官方机制支持方案可行，但本次没有实际验证应用窗口、关窗清理或退出博客后存活。

## 3. AI 辅助添加源码项目

建议流程：

选择项目目录 → 本地读取必要文件 → 规则识别 → AI 补充分析 → 展示可编辑的启动配置 → 保存登记并生成卡片。

本地读取限于 package.json 的 scripts/engines/packageManager/workspaces、锁文件名称、README 启动段落和必要的框架配置。跳过 node_modules、构建产物、.git、.env 和凭据文件；限制文件大小、数量及目录范围。AI 看到的是这些筛选后的内容，不上传整个项目。

分析输出应包含：
- 工具名称、简介与图标候选。
- 项目目录及真正的运行子目录。
- npm / pnpm / yarn 等包管理器。
- 启动脚本及额外参数，例如 npm run dev。
- Node 版本与依赖准备状态。
- 访问地址、端口与就绪检测方法。
- 判断依据和仍需补充的配置。

常见项目先根据实际 scripts 和锁文件识别，AI 负责解释和处理歧义。AI 不可凭空保证任意项目一键启动；没有启动脚本、需要数据库或多个服务时，显示缺少条件和可编辑配置。不自动安装依赖、不自动执行 README 指令、不自动修改源码。分析失败或未配置 AI 时，保留手动登记入口。

启动方式分析复用博客当前文字模型，使用专用任务提示，不改变小卿系统提示词、不写入聊天记忆。启动时使用已保存的配置，不必每次重新请求 AI。项目启动文件改变时提示重新分析或编辑配置。

npm 的 pre/post 生命周期脚本也可能运行，登记界面应一并显示相关启动链。Windows 的 npm.cmd 不能当普通 exe 直接执行；推荐定位 node.exe 与 npm-cli.js，使用明确参数调用。复杂多服务或自定义 Shell 流程需要单独的启动步骤配置，不将 AI 输出字符串直接交给任意 Shell 执行。

依据：[npm scripts](https://docs.npmjs.com/cli/v11/using-npm/scripts/)、[Node 子进程](https://nodejs.org/api/child_process.html)。

## 4. 独立应用窗口

用户要求的是工具自己的浏览器应用窗口：无博客导航、无正常浏览器标签栏及新增标签按钮，保留正常窗口关闭、最小化和最大化。

推荐先验证系统 Edge 的应用模式，Chrome 可作为备选。每个工具使用专属持久浏览器数据目录，避免转交用户已打开的普通浏览器窗口。应用模式参数与当前 Edge 的具体行为仍需运行验证；Edge 官方支持把网站作为独立应用打开。

普通网页中的外链或登录弹窗可能另开窗口，应用窗口不是浏览器禁用策略。应维持主工具窗口没有标签栏，不修改用户浏览器设置，也不承诺阻止用户在其他浏览器窗口中新建标签。

独立监管器通过浏览器控制协议识别主页面及对应窗口，结合专属浏览器实例确认主窗口关闭。刷新、导航、iframe/worker 结束、登录弹窗关闭均不能误当成主窗口关闭；短暂失联应重连核验。浏览器崩溃时清理所属工具服务。

依据：[Edge 网站应用](https://support.microsoft.com/en-us/edge/install-manage-or-uninstall-apps-in-microsoft-edge)、[Edge 独立应用窗口](https://learn.microsoft.com/en-us/microsoft-edge/progressive-web-apps/how-to/best-practices)、[Edge DevTools Protocol](https://learn.microsoft.com/en-us/microsoft-edge/devtools/protocol/)、[Chrome 独立调试资料目录要求](https://developer.chrome.com/blog/remote-debugging-port)。

## 5. 服务与窗口生命周期

建议链路：

工具卡片 → 独立监管器 → 项目服务就绪 → 工具应用窗口

监管器运行在稳定用户目录，脱离博客进程及其输入输出通道。日志由监管器写文件，不能依赖博客窗口保持连接。

- 退出博客：工具窗口、监管器和工具服务继续运行。
- 关闭工具主窗口：监管器停止所属服务及其子进程，再退出。
- 再次点击运行中的卡片：复用服务并激活既有窗口。
- 重新打开博客：通过本地实例握手恢复真实运行状态，不仅相信上次保存的“运行中”。
- 停止/重启：只针对本启动实例，先正常结束，超时再清理所属进程树。
- 浏览器或监管器异常退出：清理所属进程并记录原因，避免残留 Node 服务。

实例身份至少包含随机实例 ID、监管器进程创建时间、项目真实路径及启动配置指纹。端口被占用或进程身份不符时显示诊断，不杀未知程序。Windows Job Object 可用于监管器拥有的工具进程树，需要原生辅助实现与实测，博客不能持有该 Job 的清理责任。

工具启动环境按运行必需项重新组装，不全量继承博客数据库、站主密码、会话密钥或 AI 凭据。项目自己的环境文件继续由项目原来的启动流程处理。

就绪检查结合自有进程状态与 HTTP 响应，不能把“端口已有响应”直接当成工具已启动。Vite 默认可能更换被占用端口，需要明确实际访问地址或固定端口策略；不能给所有框架盲目附加同一种端口参数。

依据：[Node detached 与独立日志](https://nodejs.org/api/child_process.html#optionsdetached)、[Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、[Vite server.port/strictPort](https://vite.dev/config/server-options#server-port)。

## 6. 软件、目录及登记数据

.lnk 直接交给 Windows 打开，保留其启动参数及工作目录。exe 可直接登记，也可选择已有快捷方式。支持把 .lnk 或 .exe 拖到工具链页面，解析后进入图标、名称及路径的登记预览，保存生成卡片；拖入时不启动软件、不移动文件、不上传文件。移除卡片只删除登记，不卸载软件或删除源码。软件自身的退出由软件负责，不套用源码项目的关窗停止规则。

源码项目关联原目录，无须搬进博客。tools/ 可以保留给未来独立开发的工具，但第一版不要求已有项目包含博客专用工具描述文件，也不自动创建或改写该文件。

登记、运行状态、日志与每工具浏览器数据目录放在稳定用户目录，不进入博客云同步，不放在会被便携升级替换的发布目录。项目源码、依赖和业务数据由项目自己管理；复制项目后仍按自己的说明启动。

右键菜单按类型提供：
- 软件：打开、打开文件所在位置、收藏、编辑登记、移除入口。
- 源码项目：打开窗口、停止、重启、查看日志、打开项目文件夹、编辑启动配置、重新分析、移除入口。
- 网页：打开网页、复制地址、收藏、编辑、移除入口。

软件与项目启动能力仅向桌面站主开放；桌面原生调用以已登记工具 ID 为入口，不向页面暴露任意命令执行。网页只接受明确的 HTTP/HTTPS 地址。

依据：[Electron shell](https://www.electronjs.org/docs/latest/api/shell)、[Electron 文件与目录选择](https://www.electronjs.org/docs/latest/api/dialog)。

## 7. 设计图修订

原“内嵌文本处理台”设计已停用，不作为当前验收稿。下一套设计建议仍用五张：
1. 三类工具门户：本机软件、源码项目、网页工具；搜索、分类、收藏、排序、运行状态。
2. 添加源码项目：目录选择、AI 分析过程、启动方案和可编辑配置。
3. 软件与网页登记：快捷方式选择、名称/分类/标签、网址。
4. 运行管理与独立工具窗口：日志、环境诊断、停止/重启；窗口外观不附带博客导航。
5. 窄屏门户及登记布局。

本批继续遵循先设计验收、后功能开发的顺序。原计划中内嵌工作区、文本处理台和工具 AI 能力网关不进入本次启动门户范围。
