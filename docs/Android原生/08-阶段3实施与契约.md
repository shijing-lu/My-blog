# 第3阶段：离线同步底座

2026-10-07，用户批准进入第3阶段。本阶段只用随心录交付真实闭环；完整正文预览、历史搜索及其他业务模块按原计划交付。

## 实施顺序

1. 双方言同步表、主库原子事务、随心录写入版本登记；移动同步接口与服务端回归。
2. Room本地记录、草稿、outbox、游标、冲突副本；Keystore加密私人正文。
3. Repository订阅Room Flow；离线编辑与草稿恢复；WorkManager联网约束和退避重试。
4. 原生随心录列表、编辑页、同步状态与三份冲突手动处理。
5. 真机与接口验收、APK及验收记录；停止等待用户测试。

## 同步协议 v1

`POST /api/mobile/v1/sync`仅接受站主Bearer。请求包含protocolVersion、serverId、cursor与operations；每项包含opId、recordId、baseRevision和payload（null代表删除）。payload保留title/content/tags/createdAt/updatedAt。

服务端在主库事务中登记Web/桌面已有记录的变化，再用baseRevision执行CAS；opId和请求摘要绑定，响应丢失后相同操作重试返回同一确认；不同内容复用opId被拒绝。单批最多50项操作，手机按编码后UTF-8大小控制在1MB内，服务端上限1.2MB；拉取每页100条，游标与删除墓碑持久保留。每次工作最多处理50页，达到上限仍有数据时从已保存游标继续重试，不提前标记同步完成。冲突返回远端副本，手机保留base/local/remote。选择本地后基于最新远端版本重新提交；远端再次变化仍应冲突。

Web随心录CRUD与同步记录同事务落库；编辑器携带基线版本，遇到409保留输入。旧桌面同步引擎直接写库的变动在下一次同步事务中对账登记，保留其原有冲突备份；本阶段不改造其他内容的旧同步协议。

本地数据按serverId隔离。Room正文、草稿、outbox和冲突内容用Android Keystore AES-GCM加密；界面模型和网络DTO分别转换。编辑先保存加密草稿，点击保存时记录与outbox同事务落库；飞行中的操作不改写，后续编辑保留新的草稿/待提交修改。远端拉取不能覆盖有待同步修改的记录。

会话失效停止上传，保留草稿和队列；换站点只切换分区。启动、手动同步、本地保存和恢复网络触发同步；浏览列表只读取Room，不触发全量同步。WorkManager使用联网约束、唯一任务与指数退避，不排队执行认证或撤销。

## 依赖核对

沿用锁定版本；本阶段启用Room2.8.5、WorkManager2.12.0。Room实体/DAO以Java注解处理器生成，实现由Kotlin Repository封装，避免额外引入KSP版本组合。依据[Room发布记录](https://developer.android.com/jetpack/androidx/releases/room)与[WorkManager发布记录](https://developer.android.com/jetpack/androidx/releases/work)。

## 验收重点

离线编辑、杀进程草稿恢复、同事务队列、响应丢失幂等、Web并发冲突、删除传播、分批游标、会话失效保留数据、不同站点隔离、后台联网恢复。所有实际检查结果写入第3阶段验收记录。
