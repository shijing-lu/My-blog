# 小卿 AI 助手：聊天化 + 记忆 + 养成 —— 需求澄清（阶段一）

## 一、我的理解（请核对）

| 维度 | 我的理解 |
|---|---|
| 目标 | 把小卿从「选中文字的即问即答工具」升级为**常驻聊天助手**，并且只对站主**长期记忆**、能**越聊越熟** |
| 新增入口 | `src/components/RightToolbar.astro`（右侧悬浮工具栏）增加 AI 图标 → 点击唤起聊天窗口 |
| 聊天化 | 从「一次选中文本 → 一问一答」变为**自由多轮对话**（不依赖选区） |
| 记忆 | 站主：跨会话记住聊过的信息（身份、偏好、正在做的事）；**访客：不记忆**，每次都是新的 |
| 个性化 | 设置页可自定义小卿的**性格/风格/称呼**等（现有 `systemPrompt` 只是自由文本，需评估是否结构化） |
| 养成 | 按互动频次/深度积累「熟悉度」，呈现在 UI 上（等级/状态/称呼变化），目标是「AI 宠物/精灵」的陪伴感 |
| 权限 | 站主（`isTopAdmin`）→ 唤起记忆 + 应用个性化；管理员（`isManagerSession`）/ 游客 → 客人待遇（无记忆，或按你的选择各自独立） |

## 三、默认假设（未获你确认前，我按这些推进）

- **A1** F2（选中文字右键）**保留**，与 F1（图标唤起）共用同一个对话面板与同一份历史。
- **A2** 记忆存储放在**本地/云端数据库**（新增表），而不是 localStorage；结构为「长期事实摘要 + 最近 N 轮原文」。
- **A3** 记忆**仅站主**（`isTopAdmin`）拥有；管理员与游客各自只有当前会话内的上下文。
- **A4** 记忆注入有**token 预算上限**（默认摘要 ≤500 token + 最近 6 轮），超预算先压缩摘要。
- **A5** 养成度是**本地计算的派生指标**（消息数、活跃天数、连续天数、被采纳次数），不额外调用模型。
- **A6** 人格设置采用**结构化字段 + 自由文本兜底**（语气、称呼、性格标签、回复长度、口头禅 + 自定义 systemPrompt）。
- **A7** 记忆可**一键查看/单条删除/全部清空**（隐私底线）。
- **A8** 未配置 API Key 或 `enabled=false` 时，入口图标隐藏（与现有一致）。

## 四、待确认问题清单（可直接按编号回答）

### P0（不定就没法动工）

- **Q1 记忆存哪？**
  (a) 新增本地库表 `ai_conversations` + `ai_memories`（随同步上云，桌面端同样生效）← 我推荐
  (b) 只扩展现有 localStorage（不跨设备、桌面端各自一份）
  (c) 云端向量库（RAG，成本与复杂度最高）
- **Q2 记忆粒度？**
  (a) **摘要式**：每次会话结束让小卿总结 3~5 条长期事实 + 保留最近 N 轮原文 ← 我推荐（省 token、可控）
  (b) 全量对话归档 + 关键词/语义检索
  (c) 只保留最近 N 轮（不跨会话，等于"没有长期记忆"）
- **Q3 谁能有记忆？**
  (a) **仅站主**（`isTopAdmin`）；管理员/游客共用"客人待遇" ← 你的描述与推荐
  (b) 每个登录用户各自独立记忆（需要按用户隔离存储）
  (c) 站主 + 管理员共享一份
- **Q4 养成机制的口径**（这是最需要你描述的部分）：
  - 熟悉度用什么驱动？消息条数 / 活跃天数 / 连续互动天数 / 深度（长对话）？
  - 分了等级之后**具体改变什么**？（例：称呼从「你」→「老朋友」；主动关心；解锁"记住这件事"提示；界面上的小卿形象状态）
  - 是否需要**可视化形象**（图标随等级变化/小动画），还是只要文字状态？
- **Q5 聊天窗口形态？**
  (a) 复用现有悬浮小窗，点图标后固定停在右侧 ← 我推荐（改动小、体验一致）
  (b) 右侧抽屉（占一条侧栏，可展开/收起）
  (c) 独立全屏对话页（`/chat`），工具栏图标跳转

### P1（影响设计但可给默认）

- **Q6 人格设置字段**：默认给「称呼 / 语气（如温和·简洁·俏皮）/ 性格标签 / 回复长度 / 口头禅 / 自定义提示词」。要增删哪些？
- **Q7 访客体验**：访客点开图标 → 是「只读介绍页（说明小卿是站主专属）」还是「可聊天但无记忆、且明确告知」？访客能否看到养成状态？（建议：可聊、无记忆、不显示养成）
- **Q8 记忆可见性**：设置页是否需要「记忆管理」界面（查看/删除单条/清空）？（建议要，隐私底线）
- **Q9 桌面端一致性**：记忆是否要经云同步在 Web 与桌面端共享？（建议是；代价是新增表要登记同步策略 + 云端补表迁移）
- **Q10 敏感信息**：记忆里若出现密码/密钥类内容，是否要自动脱敏或拒绝写入？（建议：写入前过滤，且提供一键清空）

## 五、阶段一必答项（模式 B）

| 必答项 | 我的默认（待你确认） |
|---|---|
| **边界与异常** | API 未配置/关闭 → 图标隐藏；上游超时 60s（现有）→ 提示可重试；记忆读写失败 → 降级为无记忆对话（不阻断聊天） |
| **数据来源与归属** | 记忆数据属**站主本人**，存本地库 + 可选同步；提供导出/删除 |
| **权限模型** | 读记忆/写记忆 = 站主（`isTopAdmin`）；聊天本身 = 站主/管理员直通，游客受 `allowGuests` + 每日限流约束 |
| **并发量级** | 单用户单会话（同一时刻一条流）；新增每日记忆写入上限，避免刷爆存储 |
| **失败重试** | 流式中断 → 保留已生成内容，可「继续」；记忆写入失败 → 记日志 + 下次会话重试，不阻塞 |
| **向后兼容** | 旧 localStorage 历史 → 首次打开时迁移为当前会话；`ai` 配置键**向后兼容**（新增字段用默认值，老记录可直接读） |
| **埋点与可观测** | 记录：会话数、消息数、记忆写入/命中次数、上游错误率（写入 `launch.log` / 服务端日志；不引入第三方） |
| **上线与回滚** | 纯增量（新表 + 新端点 + 新 UI 区块）；回滚 = 关闭开关/隐藏图标，旧 F2 能力不受影响；DB 新表不回滚（无破坏性） |

## 六、建议的明确不做（Out of Scope，防蔓延）

- ❌ 不做多用户/团队共享的 AI 知识库
- ❌ 不做语音输入输出、图片理解（本期只做文本）
- ❌ 不做自建模型/微调（继续走 OpenAI 兼容 API）
- ❌ 不做跨账号社交（小卿只服务本站）
- ❌ 不引入向量数据库（除非 Q1 选 c）
