## 1. 项目概述

将 Cadence 已实现的个人计划与时间管理能力整合进博客，在博客主导航增加“日程”入口。它与现有“日历”并列：日历继续提供重要日期、日记、传统待办和农历；日程提供计划制定、时间安排、执行记录与周期复盘的完整闭环。

整合的重点是复用 Cadence 已有的领域模型、用例规则和交互行为，并把界面、路由、账号权限、持久化和同步适配到博客。新功能必须使用博客当前的颜色、字体、卡片、圆角、导航和页面布局；不能让嵌入区域看起来像另一个独立产品。

## 2. 目标用户与权限

- 唯一业务用户为站主本人；仅站主身份可以打开日程页面、读写日程 API、执行导入导出和处理同步冲突。
- 匿名访客和普通授权管理员均不得读取计划、待办、执行、复盘或日程详情。鉴权必须在服务端页面和每个 API 入口执行，隐藏前端入口不构成访问控制。
- 数据可保存在多台设备的本地副本，并与博客服务端同步；离线期间允许继续读写本地副本。

## 3. 功能需求

### 3.1 导航与信息架构

| 编号        | 需求                                                                                        | 优先级 |
| ----------- | ------------------------------------------------------------------------------------------- | ------ |
| FR-ENTRY-01 | 博客主导航新增“日程”，链接至 `/schedule`；当前页有博客现有风格的活动态                      | P0     |
| FR-ENTRY-02 | 保留 `/calendar` 和主导航“日历”，既有重要日期、日记、农历及传统待办行为不回归或丢失         | P0     |
| FR-ENTRY-03 | 日程区包含总览、计划、时间日程、执行、复盘、待办、统计和设置视图，并在窄屏可用              | P0     |
| FR-ENTRY-04 | 保留 Cadence 常用键盘操作、适当的 reduced-motion 行为和清晰的焦点状态，样式遵循博客设计系统 | P1     |

### 3.2 计划与每日计划

- 创建、编辑、状态流转、归档及软删除长期计划；计划可含最多三层任务/子任务，支持排序、标签、日期、估算时长与进度汇总。优先级通过待办 XY 维度表达，原任务实体没有独立优先级字段。
- 支持每日计划清单，可从长期任务加入今日计划，也可把每日计划项推上待办看板；计划、每日计划、任务和日程之间的完成联动遵守 Cadence 现有单向规则，避免双向循环。
- 软删除项进入回收站；支持恢复和彻底清除。删除长期数据必须提供确认。

### 3.3 时间日程与执行

- 以 24 小时纵向时间轴显示某日安排；双击空档创建，支持拖动平移、调节时长、编辑标题/备注和删除。
- 时间以 15 分钟吸附，最短时长 15 分钟；v1 不跨午夜。重叠安排拒绝提交并提示原因，不进行造成假状态的乐观落库。
- 日程可关联计划任务或每日计划项；完成联动遵守 Cadence 现有业务规则。
- 支持启动、暂停、恢复、结束计时，手动补录执行记录，同一时刻只允许一个活动计时器。计时依据时间戳和累计暂停时长计算，重载/网络中断后可恢复。
- 日程区全局可见当前计时状态；执行记录包含开始/结束、有效时长、关联任务、备注和累计暂停时长。

### 3.4 复盘与待办

- 复盘周期可设置小时长度、当天锚点、启用状态和提示语；周期格由配置和日期派生，设置变化后历史内容仍可按日期查看。
- 周期复盘使用自由文本记录事项与回顾，可标记 1–5 分心情；完成事项、阻塞和下一步不是原源码已实现的独立字段。结束执行后可打开所在时段的复盘编辑器。
- 待办支持创建、完成、编辑、归档、回收站，实体保留标签和截止时间；支持 XY 双轴分类、象限/区域配置、拖动改坐标，以及每日计划项推上待办看板。

### 3.5 总览、统计、倒计时与助手

- 总览显示今日计划进度、执行时长、待复盘格、今日时间轴、待办分布和快捷操作。
- 统计按 Cadence 既有口径显示执行时长、计划完成、复盘完成和趋势；倒计时按目标时刻计算剩余量，可在总览展示并管理多个目标。
- 提供 Cadence 自然语言助手能力：无 LLM 配置时使用本地规则；可选接入博客已有 AI 能力或兼容接口，但 AI 只通过与 UI 相同的用例执行操作。参数不足或意图不明必须澄清；删除类操作必须二次确认；不得猜测或虚报结果。
- 主题最终服从博客现有主题；不迁移 Cadence 独有外观开关，除非它能映射到博客现有主题能力。保留数据导入、JSON 导出及执行/复盘 CSV 导出。

## 4. 数据、同步与隐私

- 每台设备保留 Cadence IndexedDB 本地副本；联网后根据共同同步基线比较本地与服务端版本：只有本地变化则推送，只有远端变化则拉取，无变化则跳过。
- 同一条记录在共同基线后两端都发生变化时，标记为冲突并保留双方内容副本；站主在冲突界面选择采用本地或远端版本。禁止静默覆盖冲突内容。
- 删除必须有可同步的墓碑，避免另一台设备把已删除记录重新推回来。同步中断可重试且幂等；本地可继续操作并显示待同步/冲突状态。
- SQLite 与 PostgreSQL 均须保存同一组 Cadence 业务数据并保持字段语义一致。浏览器不得直连数据库，只能经受站主鉴权的博客 API 同步。
- 支持 Cadence JSON 导出包导入。先校验格式、版本和全部记录，再展示导入摘要；导入失败必须原子回滚或不产生部分导入。重复 ID 和既有数据冲突须在导入确认前明示处理策略。

## 5. 非功能与验收

- 视觉与交互遵循博客现有 `BaseLayout`、CSS tokens、Tailwind/shadcn 风格组件及已使用的动效约定；浅色、深色、窄屏、键盘焦点与减少动效场景均可读可用。
- 用户输入经框架转义和服务端 schema 校验；API 校验身份、请求体大小、字段类型及业务规则；日志中不写入计划正文等敏感内容。
- 页面/API 在访客和普通管理员会话下均拒绝；站主会话可正常读写。不同设备离线新增、单侧更新、双侧同记录冲突、删除传播和恢复网络重试均有验收覆盖。
- Cadence 的核心用例规则有单元测试；API、同步、迁移和权限有集成测试；关键工作流有浏览器端到端验收。发布构建通过后，仍需人工检查博客视觉一致性和桌面端入口。
- 导入前后数据可导出比对；原 `/calendar` 现有重要日期、日记和传统待办用真实历史数据做回归检查。

## 6. 范围边界

- 本期不开发多用户协作、公开日程分享、第三方日历订阅、邮件/系统级推送或 Cadence 原生 Tauri/Capacitor 安装包。
- 不迁移 Cadence 文档标注为路线图或未实现的功能；按源码和其“已实现”模块文档盘点能力，实施前逐模块核对。
- 不把博客原“日历”页面改造成日程面板，也不删除原有日历数据表。

## 7. 左侧导航与总览方卡（2026-09-30）

- 总览、计划、日程、执行、复盘、待办、统计、设置按现有顺序置于左侧导航；1024px 起显示 152px 侧栏，滚动时停靠博客导航下方。窄屏通过菜单打开左侧抽屉，切换页面后关闭，支持 Esc 和点击遮罩关闭。
- 总览顶部倒计时、今日计划、今日时间安排为等大的方卡，最大边长 280px、间距 16px。根据正文容器宽度，700px 起三列、460px 起两列，其余单列。
- 标题和主要操作固定，正文独立纵向滚动。倒计时保留全部管理操作；计划添加区固定底部；长标题换行，不出现横向滚动。
- 收紧标题与模块留白，使常见桌面窗口首屏同时呈现方卡和下方投入、复盘信息。保持原主题、路由、数据及同步行为。
