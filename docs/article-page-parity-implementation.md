# 首页文章页面返工与双域目录右键：开发计划手册

> 状态：仅计划，2026-09-28；本轮不编写功能代码。先读 [需求规格](article-page-parity-requirements.md) 和 [技术设计](article-page-parity-design.md)。本计划替代 `article-editor-and-portable-plan.md` 中“首页编辑页仅复用 Markdown 编辑能力”的页面方案；此前已完成的草稿/发布和便携版更新提示逻辑仍需保留。

## 1. 实施原则与完成定义

以用户提供的文档文章截图作为页面基线：开发完成时，首页文章编辑页与文档文章页使用同一全局框架、左树、中栏正文、右 TOC 与原位编辑切换；文章专属属性通过设置入口添加。两域左树均以右键悬浮菜单执行节点操作，目录可新增文章和目录，文章仅编辑/删除。首页文章分类升级为可嵌套目录，删除目录不删除文章。

完成定义包括：功能代码、双库迁移与同步、明确失败反馈、人工界面对照、必要的构建与回归、固定 `release/portable` 原目录的便携包覆盖。**文档阶段到此为止；本轮不执行以上代码步骤。**

## 2. 阶段、依赖与提交

| 阶段 | 具体工作 | 可交付/验收门槛 | 建议提交 |
| --- | --- | --- | --- |
| 0. 需求与现状冻结 | 本组三文档；保留用户截图基线；记录旧写作台与文档页面入口、API、状态桥；确认目录删除语义 | 需求、技术设计和开发计划互相一致 | `docs(editor): 规划统一文章页面与目录右键` |

## 3. 开发任务明细

### 3.1 目录迁移与数据访问

1. 检查当前 SQLite/PG 迁移版本、`article_categories` 与 `article_post_categories` 实际列，备份真实数据快照供回滚验证。
2. 新增 `parent_id` 可空列、父索引；旧数据保持根级。补全同步表列清单与版本兼容处理。
3. 增加目录树构建、祖先链/环校验、同级重排、路径计算和“未分类”合成视图；用稳定排序避免 UI 抖动。
4. 修改创建草稿流程使目录归属原子化；修改目录删除为事务操作：直接文章解除归属、直接子目录提级、删除目标目录；校验实际影响数。文档域级联删除保持原实现。
5. 审查旧分类管理、列表过滤、分类统计及文章移动：不能因新增层级而只显示一级分类或按名称误命中。

### 3.2 共用页面

1. 从文档页列出所有 `#doc-*`、`data-*`、全局事件桥、TOC 切换、缓存和视口协议；标出纯 UI 与文档专属服务调用。
2. 抽 Shell 时先维持文档路由标记和尺寸，避免一次性改掉全部选择器；将状态管理作用域收敛到页面根节点。
3. 统一树节点视图模型、当前高亮、展开记忆、导航 URL 与滚动；文档适配器维持 `/doc/:bundle?article=:id`，首页适配器维持 `/edit/:id`。
4. 统一正文预览与 TOC 生成、长文延迟渲染、编辑定位；首页额外设置采用插槽，服务端 SSR 初始化与客户端切文一致。
5. 拆旧 `LiveEditor`：只迁移文章业务字段/保存逻辑；不把旧全高三栏 DOM 嵌进新 Shell。确认 `AdminLayout` 不再控制 `/edit/[id]` 页面外壳。

### 3.3 右键菜单

1. 对左树根/目录/文章建立命令表，目标只能是 `root | folder | article`，域命令由适配器实现。
2. 委托监听 `contextmenu`、键盘菜单键/`Shift+F10`、触屏长按和“更多操作”；避免正文编辑器右键被拦截。
3. 菜单定位、碰撞处理、焦点循环、Escape/外部点击关闭、背景滚动与快速连续点击处理；不为每行挂单独全局监听器。
4. 移除旧行内＋文/＋目/编辑/删除按钮，保留根按钮及“更多操作”。目录“新增文章”直接创建空白并编辑；“新增目录”只输入名称；文章“编辑”导航/原位开启。
5. 删除确认显示范围；文档目录明确级联，首页目录明确保文章/提级。服务端出错树不变，成功后原位更新，不刷新整页。

## 4. 人工验收矩阵

| 场景 | 检查点 |
| --- | --- |
| 首页旧文章进入编辑页 | 全站顶部、面包屑、220px 左树、中间标题/正文、右 TOC 与文档截图同构；文章专属设置可达 |
| 首页新草稿 | 在根和三级目录分别新建，立刻选中并处于可视编辑；草稿不公开；发布后公开 |
| 文档新文章 | 在根和三级目录新建，立刻可视编辑；保留文档现有公开规则 |
| 目录右键 | 根、目录、文章分别出现精确菜单；文章没有新增项；左键、拖拽及正文 Markdown 右键各自正常 |
| 菜单替代入口 | `Shift+F10`/菜单键、触屏长按、行尾更多按钮可完成同样动作；Esc 后焦点归位 |
| 删除 | 文档目录级联；首页目录直接文章归未分类、直接子目录提级且内部文章保留；取消或失败不修改树 |
| 树操作 | 深层创建/移动、跨目录重名、环校验、根级、未分类、旧平面分类迁移后路径与排序正确 |
| 编辑/预览 | 首次可视化、往返无源码首屏、TOC 跳转、保存状态、切文/离页保护、长文与含表格/多栏/画廊的正文 |
| 文章专属 | 标签、类型、摘要、封面、访问密码/提示、发布、思维导图仍可操作；加密正文不泄露 |
| 双端/便携 | PG 与 SQLite 迁移和同步后层级一致；便携版构建并覆盖原 `release/portable`；启动无更新弹框 |

## 5. 失败、回滚与交付

- **数据库升级失败**：停止启用新目录 UI，保持旧表可读；不得自动清空分类。备份与迁移脚本用于恢复；线上先迁移、再启用依赖 `parent_id` 的代码。
- **页面共用组件回归**：每个阶段独立提交，可回退 Shell/适配器提交；避免把迁移与视觉重构绑在同一提交中。
- **便携版覆盖**：用户已退出实例，但本轮明确“先不要写代码”。等新页面与右键功能实现并检查后再重建一次，直接覆盖固定目录，不创建新的交付文件夹；覆盖前再次确认无进程占用。
- **旧计划关系**：`article-editor-and-portable-plan.md` 中已完成的便携更新、文档空白新建、草稿发布/权限保留；“首页编辑页仅复用编辑能力”的实现目标由本组三文档替代。

## 6. 模型与额度建议

采用 **GPT-6 Sol Medium** 做大多数实现：文档页抽组件、目录 API、菜单与日常修复都需要跨文件判断，Sol Medium 是质量与额度的稳妥起点。对**迁移和同步/删除事务的设计审查**，以及**共用编辑生命周期的最终架构审查**，建议临时切到 **GPT-6 Astra Medium**；审查结束切回 Sol Medium。若出现复杂数据竞争或长文视口回归再按问题升级 Astra High；不建议全程使用最高推理档。范围明确的小文案/CSS 收尾可考虑 Luna Medium，但涉及目录删除或密码权限的改动继续交给 Sol/Astra。

这是工作负载建议，不是对你账户剩余额度的测量；Codex 与 API 的实际可用性和配额以当前客户端为准。OpenAI 官方将 Sol 定位为日常写作/编码，Astra 定位为复杂分析，并建议以同一任务样本比较可接受质量与消耗：[模型选择](https://developers.openai.com/api/docs/guides/model-selection)、[代码生成](https://developers.openai.com/api/docs/guides/code-generation)。真正需要切换时我会停下来提醒你。
