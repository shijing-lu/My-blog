# Markdown 拖拽导入技术方案

## 接口

新增 `POST /api/doc/import`，请求参数为 `bundleId`、可空 `parentId`、`filename` 和客户端生成的 `operationId`，请求体是原文件字节。使用有界流读取，超过大小限制立即拒绝；解码和字符数检查通过后才写入。

文章分类适配使用 `POST /api/articles/import`，`parentId` 为分类 ID，省略表示未分类。两种接口复用有界读取、UTF-8 解码及文件参数校验。文章和分类关联在同一事务中插入，保留 SQLite 同步事务与 PostgreSQL 异步事务的差异；文章默认 `published=false`，幂等重试不会覆盖作者修改。

服务端再次校验 `docs` 权限、本册存在以及目标节点确实为同册目录。响应使用 `private, no-store`。写入沿用 `doc_nodes` 和 `createDocNode`，节点排在目标目录末尾。每个文件的 operationId 作为节点 ID，用于失败重试时避免重复创建；相同 ID 对应不同内容则拒绝。

文档排序通过数据库聚合 `MAX(sort)` 计算，不加载本册其他文章的正文。

## 客户端

- 仅外部文件拖拽进入导入流程；现有文章移动使用原有流程。
- `XMLHttpRequest.upload` 提供字节上传进度；上传完成后明确显示“正在保存”，服务器返回成功才统计为已导入。
- 文件顺序上传，大小与后缀先在客户端检查，再由服务端复核。
- 两处调用各自现有目录重绘函数，合并返回的节点元数据。共用 `installMarkdownFileDrop`，通过接口地址、根目录名称及节点回调适配不同页面。正文不写入页面节点元数据，避免大批量导入增加首屏内存。
- 进度浮层可以取消后续文件；当前已发送的保存请求完成后结算，防止已保存内容被误判未保存。页面离开时清理监听器并提示正在进行的任务。

## 兼容性

浏览器及 Electron 使用 Web 文件拖拽能力；不暴露文件系统路径、不新增 preload 权限。既有数据库迁移、Markdown 渲染和云同步机制不需要改变。
