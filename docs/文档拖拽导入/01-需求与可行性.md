# Markdown 文件拖拽导入

## 可行性结论

可实施。现有文档使用 Markdown 正文存储，目录树已经支持拖拽落点和就地重绘。新增文件读取、上传和进度反馈即可，无需常驻后台、目录扫描或上传时渲染 MDX。

单次最多 20 个文件，单文件最多 2 MiB 且解码后不超过现有正文限制 500000 字符；串行处理，不同时载入整个批次。主要开销为当前文件的传输、解码和数据库写入。这里是基于代码路径的资源评估，尚未实测大批量耗时。

## 需求

- 有相应管理权限时，可以从 Windows 文件管理器拖入 `.md` 或 `.markdown` 文件。文档文章页落到左侧本册目录；首页文章编辑页落到左侧分类。两处共用上传队列及进度浮层。
- 拖到实际文件夹时，高亮目标；拖到文章行时采用该文章所在文件夹。
- 按用户澄清，落点均为左侧实际目录或分类，右侧文章 TOC 保持标题导航。
- 弹出与站点主题一致的进度浮层，显示当前文件、上传进度、保存状态、成功和失败数量。单个失败不影响后续文件，失败项可以重试。
- 文件名去扩展名后作为文章标题，正文原样保存，包括项目扩展语法。重复文件名创建新文章，不覆盖现有内容。
- 首页文章导入后先保存为草稿，文档导入后遵循现有本册文章展示规则。
- 成功后即时更新本册目录，不刷新页面，不切走当前正在编辑的文章。

## 范围

支持 UTF-8 文本及 UTF-8 BOM。非 UTF-8 文本提示转换编码，不自动猜测编码。此次只导入 Markdown 文件；本地图片、附件和相对路径不会随文件自动上传或改写。文件夹递归拖入不属于此次范围。
