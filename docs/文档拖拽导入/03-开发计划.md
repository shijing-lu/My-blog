# Markdown 拖拽导入开发计划

1. 评估已有目录树、权限、创建接口和编辑状态保护；确认低开销串行方案。
2. 编写需求、技术和开发计划。
3. 增加有界文件导入接口，校验目录、编码、正文长度和幂等操作 ID。
4. 接入文档左侧目录及文章编辑页左侧分类，共用上传进度浮层；成功后就地更新目录。
5. 执行类型检查与构建检查，记录结果和真实文件管理器拖拽仍需确认的操作。

## 操作确认清单

根目录及嵌套目录落点、文章行落点、多个文件、同名文件、空 Markdown、超大文件、非 UTF-8、网络失败重试、无管理权限、上传过程中编辑文章、现有拖拽移动与客户端路由切换。

## 实施记录（2026-10-08）

- 已实现共用的拖拽上传队列、进度浮层、停止后续文件及失败重试，文档目录和文章分类分别接入保存接口。
- 服务端复用有界读取和 UTF-8 校验，文档追加只查询最大排序；文章正文和分类关联在同一事务中保存为草稿。
- 全项目类型检查存在一个既有审计测试文件的 4 个类型错误，本次新增代码未报类型错误。桌面构建成功，产物用于更新 `release/portable/resources/app/dist`。
- 真实 Windows 文件管理器拖入、实际网络失败重试和批量耗时尚未操作确认；低开销结论基于串行及有界读写设计，而非性能测量。
