# 桌面端前进与后退导航技术文档

## 现有架构

`desktop/main.cjs` 创建 Electron `BrowserWindow` 并加载本地 Astro 服务；`desktop/preload.cjs` 在 `contextIsolation` 下向页面暴露有限接口。`src/layouts/BaseLayout.astro` 是全站顶部导航的入口，桌面构建在 `<html>` 上标记 `data-desktop`，页面切换由 Astro `ClientRouter` 管理。

## 数据流

1. 主进程为每个 `BrowserWindow` 分别读取 `webContents.navigationHistory.canGoBack()` 与 `canGoForward()`。
2. 导航完成或同页历史变化时，主进程向该窗口发送 `{ canGoBack, canGoForward }`；页面初次订阅时主动查询一次状态，避免错过初始事件。
3. preload 只暴露 `goBack()`、`goForward()`、`getNavigationState()` 和 `onNavigationStateChange(callback)`。订阅方法返回解除订阅函数；不暴露任意 IPC 通道。
4. 主进程从 IPC 事件的 `sender` 取得对应窗口，并在执行前再次检查历史是否可移动。导航状态只返回给该窗口。
5. 顶部导航按钮只在 `data-desktop` 环境出现。页面脚本负责订阅、更新 `disabled`，并在 Astro 页面切换后重新绑定当前 DOM 按钮。

## 导航边界与安全

- 使用 Electron 的 `navigationHistory`，由 Electron 管理历史栈；站内的整页导航及 `pushState` 导航触发状态更新。
- 主进程只允许本地服务地址作为桌面窗口的导航目标。外部 HTTP(S) 链接交由系统浏览器打开，避免外部页面获得桌面 preload 能力或进入站内历史。
- `contextIsolation: true` 和 `nodeIntegration: false` 保持不变。IPC 请求只能控制发起请求的窗口，不能指定其他窗口或任意 URL。
- 离线内置页不应暴露可移动的站内历史；回到服务后状态重新同步。

## 相关文件

- `desktop/main.cjs`：导航 IPC、状态广播、站外链接处理。
- `desktop/preload.cjs`：受限的页面桥接。
- `src/layouts/BaseLayout.astro`：桌面专属按钮位置。
- `src/scripts/desktop-navigation.ts`：按钮状态与 Astro 页面切换期间的事件绑定。
