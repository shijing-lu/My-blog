# 桌面端前进与后退导航开发计划

## 实施顺序

1. 扩展 Electron 主进程：为每个窗口绑定导航事件，提供读取历史状态及前进、后退请求；处理外部链接。
2. 扩展 preload：向渲染页面提供固定的导航方法和状态订阅，保持现有安全设置。
3. 在顶部导航的站名两侧增加桌面端按钮，复用网站主题样式；实现禁用态、键盘焦点和辅助技术标签。
4. 页面脚本接收状态并处理 Astro 客户端路由后的按钮重新绑定，避免重复监听。
5. 验证站内连续跳转、前进分支失效、多窗口独立、网页端隐藏、外部链接及窗口标题栏。

## 完成标准

- 后退与前进按钮准确呈现在站名左右两侧，窗口原生标题栏保留。
- 按钮状态与当前窗口历史一致，不在边界处误触发导航。
- Astro 页面切换、整页加载和新窗口下均保持可用。
- 页面只能调用受限导航接口，不能访问 Node 或任意 IPC 通道。
- 桌面构建在既定 `release/portable` 交付目录进行；若目标程序仍在运行，应通知用户退出后再覆盖。

## 开发模型

推荐 GPT-6 Luna、medium 推理。此任务边界明确，但需要协调 Electron 主进程、preload 和 Astro 页面。若联调发现复杂的客户端历史兼容问题，再使用 GPT-6 Sol、medium 推理处理该局部问题。模型选择依据：https://developers.openai.com/api/docs/guides/model-selection 。
