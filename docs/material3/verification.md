## 使用与回退

- 管理员进入“站点设置 → 外观”，设置站点默认风格；普通访客也可在个人外观面板选择当前设备的风格。
- 当前设备提供“跟随站点、现有风格、Google Material 3”，明亮、暗色和跟随系统独立选择。设备明确选择优先，其次站点默认，最后为现有风格。
- 首次升级保持现有风格。Material 暂停旧主题、手动字体、背景及自定义外观 CSS 的覆盖；旧值完整保留，切回恢复。换肤即时生效，不刷新页面或重建编辑器。
- 数据仍使用原有 settings KV、权限与同步流程，无新增表。`GET /api/ui-style` 公开读取；`PUT` 要求设置权限，非法值返回 400，保存失败保持旧设置并提示。

## 业务状态与数据验证

文章和文档使用真实 CodeMirror EditorView 执行换肤，验证编辑器及 DOM 身份、光标、撤销、折叠和完整自动保存；7516 字符源文含 H1–H6、提示块、分栏、代码、公式和表格，隐藏的折叠正文仍完整保存。阅读与编辑状态均有折叠回归，五种编辑宽度无页面横向溢出。换肤浏览器回归明确操作的是 L2 折叠，未将这一结果扩写成六级标题逐级人工验收。

设置验证了成功保存、模拟服务失败恢复选择、访客首帧、设备覆盖、刷新、跨标签页、系统变化、重新聚焦及动态自定义 CSS 的停用/恢复。相册在两种风格下验证焦点/悬停粘贴多图片、队列保持、真实 JPEG 压缩载荷、进度、失败和重试；10 次上传请求使用 mock 响应，未写真实图床。加密阅读验证未解锁时源文不暴露、错误密码提示、正确解锁、折叠与小屏显示。详见 `editor-verification.json`、`media-gate-verification.json`。

数据库证据按层次分别记录：

1. 隔离 SQLite 执行站点设置和编辑自动保存；两份 SQLite 的 API 测试验证镜像 upsert、同一时间戳、权限、非法值、保存及读取失败。
2. Vercel 构建真实连接主备 PostgreSQL：各 36 表检查通过、0 列新增；settings KV 镜像读写、失效主库后的备库读写、ORM CRUD/returning/时间戳、Cadence revision/CAS/tombstone 均通过。部署原缺少 `src/cadence/data` 源码的问题已通过把忽略规则 `data/` 限定为根目录 `/data/` 修复。
3. 使用唯一临时 settings key 和两个隔离 SQLite 执行 6 次真实 `runSync`：Material、现有风格各完成本地 A → 主备 PG → 本地 B；4 次上传/拉取各 1 行，2 次重复同步零变更。4 次主备值/毫秒时间戳核对通过，25 项范围保护拒绝自检通过。主备测试 key 删除后 2/2 不存在，本地临时数据及元数据也已清理。没有访问实际 `ui_style`、用户行或真实桌面数据库。见 `settings-sync.json`。

这些结果分别证明接口、真实主备库和真实同步路径，未以 mock 或两份 SQLite 的通过推断真实 PostgreSQL 通过，也未将临时 key 的同步扩写为真实两台设备全量数据/离线冲突验收。
