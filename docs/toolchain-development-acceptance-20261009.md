# 工具链开发与验收记录

本批实现 Windows 桌面端站主入口 `/toolchain`，位于“随心录”右侧。沿用首页暖白、橙红、黑色描边与硬阴影，复用首页猫咪，普通操作使用 Lucide。

## 已实现

- 本机软件：选择或批量拖入 `.lnk` / `.exe`，预览、登记、读取图标；直接打开原文件，保留快捷方式参数和工作目录。文件失效可编辑重新定位。
- 源码项目：选择原目录，读取受限的启动资料，检测 Node.js / 包管理器 / 依赖目录；通过现有博客订阅或 API 文字模型分析启动方式。建议可修改，保存后点击卡片启动。
- 网页工具：登记 HTTP/HTTPS 地址，点击交给系统浏览器；可复制地址。
- 共用操作：搜索、分类、标签、收藏、排序、编辑和移除。源码卡片支持停止、重启、日志、重新分析和“打开当前项目文件夹”。
- 键盘操作：卡片回车启动，Shift+F10 打开菜单，菜单方向键移动，Esc 关闭并恢复焦点；弹窗使用原生模态焦点管理。

## 独立窗口实现

采用独立 Electron/Chromium 进程承载工具窗口，界面没有博客导航、标签栏或新增标签按钮。窗口无博客 preload，无 Node/本地桥接权限，并使用专属浏览器会话。此实现取代调研阶段的 Edge `--app` 候选方案，能够直接、准确地处理窗口关闭和服务清理。

服务通过结构化参数启动，不将 AI 输出交给 Shell 求值。第一版支持 `npm run`、npm 标准脚本、`pnpm`、`yarn` 和项目内 JavaScript 的 `node` 入口。复杂命令写入项目自身 `package.json` 脚本。不自动安装依赖，不自动切换计费 AI。

服务在创建后、继续执行前被加入 Windows Job Object；该 Job 由独立工具监管进程的辅助进程持有。退出博客不停止工具；关闭工具窗口清理其服务及后代；监管进程意外退出时辅助进程也会清理服务。不会根据端口号杀其他程序。就绪检查同时确认监听端口属于自己的 Job、监听本机地址、HTTP 可用。

应用窗口刷新和 Ctrl+R/F5 不停止服务。启动中重复点击复用已有实例；重开博客通过随机实例 ID 和独立令牌重新连接运行实例。

## 数据与权限

- 登记：`%APPDATA%/byqx-blog-desktop/toolchain/registry.json`。
- 日志、运行状态、版本化监管脚本和窗口资料也保存在上述工具链用户目录。项目使用原目录，不复制或改写源码，不进入博客云同步。
- 每次原生操作检查调用窗口、主框架、工具链路径和站主本人会话。普通授权管理员无权操作。
- 两个新增 API 为访问检查和启动分析，均限制站主及桌面模式，使用 `private, no-store`；分析另外校验同源请求。
- AI 收到启动资料，不读取 `.env`、博客聊天记忆或源码全文；分析使用专用任务提示词，保持博客原系统提示词不变。
- 工具子进程只继承运行所需系统环境，不继承博客数据库、站主密码、AI 密钥或订阅凭据。

## 人工验收与当前边界

可运行 `node scripts/preview-toolchain-desktop.mjs` 打开隔离桌面预览，里面的卡片均为验收示例。正式软件不在此预览中登记。

需要你使用真实项目和已连接的博客 AI 检查启动建议、项目自身交互及窗口观感。自定义端口须与命令一致；如果服务监听所有网卡或端口被占用，会停止并显示错误。没有 Node.js / 对应包管理器时需要手动准备。部分特殊命令、monorepo 子包或自定义解释器需要选择合适子目录/项目脚本。

便携版已更新并验证实际打包运行路径；没有重打安装版或 APK。真实项目、实时 AI 启动建议及个人环境仍由站主验收。仅 Windows 桌面端开放原生工具管理。
