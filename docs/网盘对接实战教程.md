# 网盘对接实战教程：把蓝奏云接进你的博客

> 本文是一次真实对接的**完整复盘**：从安装 AList、挂载蓝奏云，到浏览器直传与故障排查，中间踩过的每一个坑都原样保留，并附上对应的定位与修复方法。
>
> - **适合谁**：想给自己站点加「上传即转存网盘」能力的个人开发者
> - **预计耗时**：首次约 1～2 小时（含内网穿透）
> - **阅读方式**：急着排障的可直接跳到[故障排查速查表](#故障排查速查表按报错找原因)

---

## 一、先搞懂架构：为什么必须有一层「中转」

一句话：**你的网站不直接跟网盘厂商对话，而是对接一个跑在你自己电脑上的 AList，由 AList 去对接蓝奏云。**

在动手之前，先想清楚为什么不能"网站直连厂商"。三道硬约束叠在一起，直接把直觉路线堵死了：

| 约束 | 事实 | 直接后果 |
| --- | --- | --- |
| 厂商开放政策 | 蓝奏云**没有官方开放 API**，社区逆向驱动（AList 已内置）在持续维护 | 自己逆向协议 = 无底洞式的长期维护负担 |
| Serverless 体积上限 | Vercel 函数的请求体 / 响应体上限均为 **4.5 MB**（全计划、无开关） | 文件正文不能经过网站服务器 |
| 浏览器跨域 | 厂商接口不返回浏览器可用的 CORS 头 | 浏览器也无法直连厂商 |

三者相乘只剩一个出口：==在网站与厂商之间，放一个不属于 Serverless 的常驻中转=={.tip}。而这正好就是「填一个中转地址 + 一组鉴权参数」的形态。

### 三条数据链路

| 链路 | 实际路径 | 关键点 |
| --- | --- | --- |
| 浏览 / 下载 | 浏览器 → 网站 → AList | 下载返回的是**直链**，文件正文不经过网站 |
| 大文件上传 | 浏览器 **直连 AList 暂存区** → 服务端通知 AList 跨存储复制到蓝奏云 | 文件正文完全绕开网站服务器 |
| 小文件上传 | 与大文件相同 | 分流阈值设为 `0` 后，**全部**走直传 |

:::tip
**把分流阈值设为 0，是本次实践中性价比最高的一个决策。**
站点部署在 Vercel（美区）时，经函数转发意味着文件正文要**两次横跨太平洋**——实测同一个 2 MB 文件：经函数 **72 秒**，浏览器直传 **5.3 秒**。
:::

## 二、准备清单

| 需要什么 | 说明 |
| --- | --- |
| 一台常驻在线的 Windows / Linux / NAS | AList 要 7×24 活着，关机 = 网盘功能不可用（博客其他功能不受影响） |
| 蓝奏云账号 | 标准版单文件上限 100 MB，优享版 500 MB |
| 一个托管在 Cloudflare 的域名 | 用于内网穿透的固定地址；NS 不在 CF 也可先用临时隧道验证 |
| 网站的管理员权限 | 用于在设置页填配置 |

:::note
蓝奏云**只接受部分文件类型**：`zip` `txt` `pdf` `jpg` `png` `mp4` `exe` `docx` 等可以，`.md` `.json` `.csv` `.js` 等代码/数据类会被直接拒绝（提示「不能上传.xxx格式的文件」）。这是厂商限制，与 AList 无关。绕过办法：先打包成 `zip`，或在 AList 里再加一个不挑类型的驱动。
:::

## 三、安装 AList 并设为开机自启

### 3.1 安装（Windows 二进制，无需 Docker）

1. 到 AList 的 GitHub Releases 下载 `alist-windows-amd64.zip`（**注意认准 amd64**，别下成 darwin / arm64）
2. 解压到一个**固定目录**，例如 `C:\alist`（不要放在「下载」或「桌面」这类会被清理的位置）
3. 初始化管理员密码：

```bash
cd C:\alist
alist.exe admin set 你的密码
```

> [!warning] 版本必须 ≥ 3.57.0
> 更早版本存在路径穿越漏洞（CVE-2026-25161），攻击者可以绕过子账号的目录限制——这会直接击穿「直传子账号」这层安全模型。安装前先 `alist.exe version` 确认。

### 3.2 开机自启

AList 没有内置的 Windows 服务安装器，常用两种方式：

:::tabs#autostart

@tab 计划任务（开机即启，推荐）

以**管理员身份**打开 CMD，执行一次：

```bash
schtasks /Create /TN "AList" /TR "C:\alist\alist.exe server --force-bin-dir" /SC ONSTART /RU SYSTEM /RL HIGHEST /F
```

- `--force-bin-dir` 强制 AList 把数据目录定在 exe 所在目录，避免工作目录漂移
- `/RU SYSTEM`：以系统身份运行，**不需要登录 Windows** 就会启动

@tab 启动文件夹（登录后启动）

在 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\` 下新建 `alist-autostart.bat`：

```bash
@echo off
cd /d "C:\alist"
start "" /MIN "C:\alist\alist.exe" start --force-bin-dir
```

`alist start` 会 fork 出一个独立守护进程后立刻返回，所以登录后不会有窗口残留。
缺点：需要登录账户后才启动。

:::

> [!note]- 为什么目录位置和自启这么重要
> 网站侧的隧道地址始终指向 `127.0.0.1:5244`。一旦 AList 没起来，就会出现「隧道活着、AList 死了」的组合：外网访问直接 502，而且很难第一时间想到是本机服务没了。把 AList 放进固定目录 + 设自启，是把这类故障从「随机出现」变成「不会出现」。
> 实测顺序建议：先搬目录、再配自启，最后启动服务——顺序反了会出现「旧实例还占着端口」导致数据目录移动失败。

## 四、挂载蓝奏云

打开 `http://127.0.0.1:5244` → 后台「存储」→ 添加，关键字段如下：

| 字段 | 填什么 |
| --- | --- |
| 驱动 | `蓝奏云` |
| 挂载路径 | `/蓝奏云`（或任意英文路径，建议统一） |
| 类型 | **账号**（见下方说明） |
| 账号 / 密码 | 蓝奏云的登录账号与密码 |
| 根文件夹 ID | `-1`（表示整个网盘根目录） |

认证方式有三种，按需选择：

:::tabs#lanzou-auth

@tab:active 账号 + 密码（推荐）

AList 会用账号密码自动登录并维持会话，**无需人工续期**。
源码里登录前会先解 `acw_sc__v2` 反爬挑战，失败自动重试最多 3 次。

@tab Cookie

从浏览器登录蓝奏云后，按 `F12` → Network → 任一请求 → 复制整行 `Cookie` 请求头粘贴进去。
有效期约 15 天，过期需要重抓。适合不想在服务里存账号密码的场景。

@tab 分享链接（只读）

只能浏览与下载，**不能上传**——与「上传转存」的需求冲突，除非你只需要下载。

:::

> [!danger] 全流程最大的坑：类型选了 Cookie，Cookie 却是空的
> AList 蓝奏驱动的初始化逻辑是「账号模式先登录，Cookie 模式直接使用已填的 Cookie 字段」。
> **类型选 `cookie` 时会完全跳过登录步骤**——如果你只填了账号密码而没填 Cookie，AList 会拿着空凭据去请求，于是出现两个一模一样根源的报错：
>
> - 存储状态：`uid variable not find`
> - 浏览目录时：`Failed get objs: failed to list objs: cookie expiration`
>
> ==两条报错是同一个根源的两个面孔=={.error}，看到其中任意一个都先检查这里。
>
> **修复**：把「类型」改成 `账号`，保存即可。修好后存储状态应从红色错误变为 `work`。

## 五、建本地暂存区

大文件不能让浏览器直接传蓝奏云（AList 蓝奏驱动的上传有 **120 秒硬超时**），所以采用「先落本地、再跨存储复制」的两段式。

1. 在磁盘上建一个目录，例如 `C:\alist-storage`
2. AList 后台 → 存储 → 添加：

| 字段 | 填什么 |
| --- | --- |
| 驱动 | `本机存储` |
| 挂载路径 | `/local` |
| 根文件夹路径 | `C:\alist-storage` |

3. 进入 AList 的 `/local`，新建子目录 `_netdisk_staging`（这就是网站的暂存目录）

:::warning
**暂存目录不要设在根路径**（`/`）。网站侧会显式校验「暂存路径必须位于配置的暂存目录内」，根路径会被直接拒绝——这是防止越权复制任意位置文件的保护措施。
:::

## 六、创建受限直传子账号（安全核心）

大文件由**浏览器**直传 AList，因此浏览器必须持有一份 AList 凭证。
**绝对不能下发管理员 token**（等于交出整个网盘的控制权），正确做法是建一个只能写暂存目录的受限账号。

### 6.1 权限位速查

AList 的权限是按位运算的，本场景只需要两个位：

| 权限位 | 值 | 作用 |
| --- | --- | --- |
| mkdir + upload | `8` | 允许新建文件夹与上传 |
| 路径限制 | `16384` | 让权限作用域真正生效 |
| **合计** | **`16392`** | 两者都要勾 |

> [!warning] 「路径限制」必须勾选
> 只勾「上传」而不勾「路径限制」，作用域完全不生效——子账号将拥有与其角色列表不匹配的能力。

### 6.2 操作步骤

1. AList 后台 →「用户」→「角色」→ 新建角色
   - 名称：`blog-uploader`
   - 权限作用域：路径 `/local/_netdisk_staging`，权限位 `16392`
2. 「用户」→ 新建用户
   - 用户名 / 密码：`blog-uploader` / 一个强密码
   - 角色：`blog-uploader`
   - **基础路径（base_path）：留空或填 `/`** —— ==这一步不做，直传必坏=={.error}

### 6.3 base_path 的坑（实测，比文档记载更隐蔽）

> [!danger] 创建用户时 base_path 会「自作主张」
> 通过 API 创建用户时即使显式传入 `base_path = /`，AList 仍可能把它设成**角色的作用域路径**（如 `/local/_netdisk_staging`）。
> 后果是子账号会把**所有请求路径当作相对路径**解析，出现一组极具迷惑性的现象：
>
> - 列 `/` → 成功（其实列的是暂存目录本身）
> - 列真实暂存目录 → `object not found`
> - 上传到任何目录 → 都"成功"（其实全落进了暂存目录内部）
>
> **修复**：创建之后**再编辑一次该用户**，把 `base_path` 显式改回 `/` 并保存。
> **验证方法**：用该子账号登录后，应能进入 `/local/_netdisk_staging`，而 `/蓝奏云` 等其他挂载点直接被拒。

### 6.4 权限边界实测（应当全部符合预期）

| 操作 | 预期 |
| --- | --- |
| 列 `/local/_netdisk_staging` | ✅ 允许 |
| 列 `/` | 允许，但**只显示通往授权目录的那条路径链**，看不到蓝奏云 |
| 列 `/蓝奏云` | ⛔ 拒绝 |
| 上传 → 暂存目录 | ✅ 允许 |
| 上传 → 蓝奏云 / `/local` 根 | ⛔ 拒绝 |
| 删除 → 任意位置 | ⛔ 拒绝 |

:::info
列 `/` 与 `/local` 是"允许"的，这是 AList 的刻意设计：放行**通往授权作用域的导航路径**，同时把无权访问的挂载点整个过滤掉。所以你在 `/` 里只会看到 `local/`，看不到蓝奏云——这不构成泄露。
:::

## 七、内网穿透

本机 AList 要被线上网站和浏览器访问，需要一个公网入口。推荐 **Cloudflare Tunnel**：免费、自动 HTTPS、不需要公网 IP、不用在路由器开端口。

原理一句话：`cloudflared` 由**你本机主动**向 Cloudflare 建立出站连接，外网流量顺着这条已建立的连接推回来——所以不需要公网 IP，也不用开任何入站端口。

1. 安装 `cloudflared`（Windows 下载 `cloudflared-windows-amd64.exe`，放到固定目录如 `C:\cloudflared`）
2. 登录 Cloudflare 后台 → **Networking → Tunnels** → Create a tunnel → 选 Cloudflared
3. 复制后台给出的安装命令（内含 token），在管理员 CMD 里执行——它会自动注册成 **Windows 服务**，开机自启
4. 在该隧道的 **Routes → Add route → Published application** 里添加：

| 字段 | 填什么 |
| --- | --- |
| 子域名 | `alist` |
| 域名 | 你的域名 |
| Service 类型 | `HTTP` |
| Service URL | `127.0.0.1:5244` |

:::warning
**Service URL 的协议别写错**：AList 本地是 HTTP，这里就必须填 `http://`。写成 `https` 会得到 502。
另外 DNS 记录由 Cloudflare 自动创建，**不要**手动再去加一条 CNAME，否则会冲突。
:::

> [!tip]- 想先零成本验证链路？
> 不配置域名也能快速试通：`cloudflared tunnel --url http://127.0.0.1:5244`，它会打印一个 `https://随机词.trycloudflare.com` 的临时地址。适合证明"这条路走得通"，但地址每次重启都变，**不能用于生产**。

## 八、网站侧配置

设置 → 网盘对接，按下表填写：

| 字段 | 值 | 说明 |
| --- | --- | --- |
| 中转服务地址 | 隧道地址，如 `https://alist.example.com` | 本地开发可填 `http://127.0.0.1:5244` |
| 管理员账号 / 密码 | AList 的 admin | 服务端列目录、转存、删除用 |
| 直传子账号 / 密码 | `blog-uploader` | **只下发给浏览器**的受限凭证 |
| 管理目录 | `/` | 管理页展示的根 |
| 暂存目录 | `/local/_netdisk_staging` | 与第五步一致 |
| 目标目录 | `/蓝奏云/blog-files` | 上传的最终落点 |
| 分流阈值 | `0` | ==0 = 全部走浏览器直传=={.tip}，这是速度的关键 |
| 单文件上限 | `100` | 蓝奏云标准版上限 |

填完点「测试连接」，会得到分步诊断结果，逐项打勾才算就绪。

## 九、验证：一次真实上传

用管理页上传一个 2 MB 左右的文件，观察两点：

1. 界面上出现「完成」，耗时应在==数秒=={.tip}级别
2. AList 的目标目录里出现该文件，且**暂存目录随后被自动清空**

:::note
网站侧的直传流程是：先向网站要一份**一次性上传凭证**（内含受限子账号 token 与净化后的目标路径）→ 浏览器 `PUT` 直连 AList 暂存区 → 通知服务端执行「暂存 → 蓝奏云」的跨存储复制 → 复制任务结束后自动清理暂存。
文件正文自始至终不经过网站服务器，这是绕开 4.5 MB 上限的关键。
:::

## 十、故障排查速查表（按报错找原因）

| 现象 | 根因 | 解决 |
| --- | --- | --- |
| 存储状态 `uid variable not find`；浏览报 `cookie expiration` | 蓝奏云**类型选了 Cookie 但 Cookie 为空**，登录步骤被整个跳过 | 类型改「账号」保存 |
| 直传报 `object not found`，且子账号"上传哪儿都成功" | 子账号 `base_path` 被设成了作用域路径而非 `/` | 编辑该用户，`base_path` 改回 `/` |
| 上传报 `file [xxx] exists` | 目标目录已有同名文件 | 换名重传，或先删除旧文件 |
| 提示 `不能上传.xxx格式的文件` | 蓝奏云文件类型白名单 | 打包成 `zip`，或换其他网盘驱动 |
| 上传"一直转圈"很久才成功 | 小文件走了网站函数转发，正文两次横跨太平洋 | 分流阈值改为 `0` |
| 外网访问 502，但本地 `127.0.0.1:5244` 正常 | AList 没起来（隧道活着但后端死了） | 启动 AList 并确认自启已配置 |
| 本地访问 `localhost` 返回 502 | 命令行环境带了代理变量 | 临时清空 `http_proxy` / `https_proxy`，或加 `--noproxy '*'` |
| 隧道配置完访问不通 | 公开域名没加，或 Service 协议写成 `https` | 检查 Routes 里是否已添加、协议是否为 `http://` |
| 测试连接提示"未配置受限子账号" | 直传子账号字段为空 | 填入第六步创建的账号密码 |

下面几个坑更隐蔽，展开看细节：

:::collapse accordion
- 复制任务完成后暂存文件还在

  AList 的跨存储复制是**异步任务**（接口立刻返回任务列表）。任务进行中源文件被占用，删除会失败。
  正确做法：轮询任务状态，结束后再删；并且**删除要带重试**——实测直传刚结束时立刻删会失败，稍等片刻就能删掉。

- 列 `/` 能看到部分目录，算不算权限漏洞

  不算。AList 会放行**通往授权作用域的导航路径**，同时过滤掉无权访问的挂载点。
  判断标准：如果子账号在 `/` 里能看到蓝奏云挂载点，或能对暂存目录之外做任何写操作，才是真漏洞。

- 手动复制单个文件一直不成功

  逐项核对：目标目录是否已存在同名文件；蓝奏云是否接受该扩展名；存储状态是否为 `work`。
  另外 AList 后台的列表有短暂缓存，删除后立刻刷新可能仍显示，等几秒再看。

- 通过 API 创建存储 / 用户时字段"丢失"

  AList 建存储接口的 `addition` 字段必须是 **JSON 字符串**而非对象；`role/create` 与 `user/create` 成功时返回 `data: null`，需要从列表接口反查 id；**用户创建后必须再编辑一次把 `base_path` 设回 `/`**。
:::

## 十一、已知限制与边界

| 限制 | 说明 | 缓解方式 |
| --- | --- | --- |
| 蓝奏云文件类型白名单 | `.md` `.json` 等无法直传 | 打包成 `zip`；或挂载其他驱动 |
| 单文件大小 | 标准版 100 MB / 优享版 500 MB | 超限在网站侧直接拦截 |
| 本机必须常驻 | 关机 / 休眠 / 断网 = 网盘功能不可用 | 固定目录 + 自启，故障时网站侧会给出友好提示 |
| 目标目录同名文件 | 重复上传同名文件会失败 | 换名或先删旧文件 |
| 隧道请求体上限 | Cloudflare 免费版 100 MB | 与蓝奏云标准版上限一致，通常不构成瓶颈 |

## 十二、上线检查清单

- [ ] AList 版本 ≥ 3.57.0，安装在固定目录
