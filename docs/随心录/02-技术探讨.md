# 随心录技术探讨

调研日期：2026-09-27  
结论性质：开发前调研；2026-09-27 已按站主私密方案落地，实际实现以源码为准。

## 1. 现有能力地图

| 需求点 | 项目现状 | 对本功能的影响 |
|---|---|---|
| 全站右侧工具栏 | `src/components/RightToolbar.astro`；由 `src/layouts/BaseLayout.astro` 挂载。工具栏当前含首页、权限相关入口、AI（配置就绪时）、回顶。 | 可在 AI 入口之后新增图标；目前工具栏全站出现，需由服务端身份/权限判定控制记录入口。 |
| 顶部导航 | `src/layouts/BaseLayout.astro` 静态导航含“归档”。 | 可在“归档”后加入口，并基于 `canManage` 控制私密页面链接。 |
| 正式 Markdown 渲染 | `src/lib/mdx.ts` 的 `renderMdx` 使用 MDX evaluate、项目 remark/rehype 插件、KaTeX、组件注册表及归一化逻辑。 | 这是正文最终渲染的权威管线，适合作为随心录预览和列表卡片渲染的统一来源。 |
| 轻量预览 | 同文件 `renderMarkdownHtml` 仅使用 remark-parse + GFM，注释亦称轻量管线。 | **不能直接用于本需求**：它不包含项目全套扩展/MDX 组件，可能让编辑预览和正式渲染不一致。 |
| Markdown 编辑器 | `src/components/admin/MarkdownEditor.tsx` 是可复用 CodeMirror 6 编辑器，有 WYSIWYG/Live Preview、图片操作及 `onSave` 回调。已用于写作台、文档、日记等场景。 | 可以复用内核，但必须盘点 `cm-live-preview` / `cm-wysiwyg` 与 `renderMdx` 插件清单的覆盖差异；不应默认宣称全量实时 WYSIWYG。 |
| 动态数据能力 | `src/lib/moments.ts` 有标签序列化、列表分页和标签/日期过滤；moments 可公开/私有混合。 | 可参考标签和分页实现，但不应复用 moments 数据：它面向公开动态并带媒体/可见性语义。 |
| 日记数据能力 | `diary_entries` 在双方言 schema 中，私密且按日期唯一；`/api/diary` 采用日期 upsert，使用 `renderMarkdownHtml`。 | “一天一篇”会覆盖当天内容，且预览不具备全扩展，均不适合作为随心录表或 API 的直接复用。 |
| 鉴权 | `src/lib/route-permissions.ts` 将日记/待办 API 绑定到 `calendar` 权限；中间件支持顶级管理员限制。 | 随心录包含私密想法，实施时将其 API 与页面限制为顶级管理员，避免已有 `calendar` 授权扩大笔记可见范围。 |
| 数据同步 | `src/sync/tables.ts` 显式登记 LWW 同步表，含 `diary_entries` 和 `moments`。 | 新表必须加入同步白名单，否则桌面/多库同步不完整。 |
| 数据库 | SQLite / PostgreSQL schema 成对维护；已有 SQLite push 与 PG migration 工作流。 | 新表要同步修改 schema、类型/领域访问层、迁移并检查两种方言。 |

## 2. 推荐架构

### 2.1 专用记录模型

新增 `quick_notes`（或 `moments` 外独立命名的 `quick_notes`）表，建议字段：

- `id`：UUID 主键；
- `title`：可空标题；
- `content`：Markdown/MDX 源文；
- `tags`：JSON 字符串数组，沿用项目标签清洗/去重约束；
- `created_at` / `updated_at`：创建与最近更新时间。

记录都是私密内容，不设置 `visibility` 字段，避免后续误把默认值当成公开开关。创建时间作为时间线日期，编辑只更新时间、不改变时间线位置。SQLite/PG schema 字段类型风格分别沿用各自现有表。

### 2.2 权限和 API

- 私密页面路由为 `/quick-notes`；全局入口名称显示“随心录”。
- `route-permissions.ts` 将 `/api/quick-notes*` 全方法限制为 `top`，页面和入口使用 `isTopAdmin`；服务端守卫是安全边界。
- 设计列表/详情读取、创建、更新、删除 API；详情按 ID 访问，写入校验正文和标签长度；GET 响应含私密数据时使用 `no-store`，不要用公开 CDN 缓存助手。
- 页面 SSR 同样做权限校验并设 `indexable={false}`；无权限页面遵循既有受保护页面处理，不在页面 HTML 中预取私密正文。
- 防止 HTML/MDX 内容作为可信可执行代码：正式 `renderMdx` 编译能力要核查对用户内容的约束，并只允许该站目前认可的 MDX 组件/语法。站主专用权限降低来源风险，但不能替代渲染边界检查。

### 2.3 Markdown 兼容策略

1. 阅读卡片和编辑器预览的最终渲染调用 `renderMdx`，确保插件与文章一致；仅在确认具体插件要求 DOM 或渲染成本过高后，才讨论专门预览 API。
2. CodeMirror 内实时装饰不等同正式渲染器：先从 `mdx-plugins.ts`、`components/mdx/registry` 和 `cm-wysiwyg.ts` 建支持矩阵，将语法分为「实时可视」「预览可见但编辑态显示源码」「目前不兼容」。
3. 悬浮记录器提供独立“编辑/预览”模式，编辑阶段复用 MarkdownEditor，预览阶段通过受保护 API 或服务端返回的同源 HTML，应用项目 `.prose` 样式与 KaTeX/代码块脚本。保存前后保持源文不变。
4. 自定义 MDX JSX/指令需重点验证：当前 CodeMirror 装饰不一定可编辑这些块；复杂图/组件如不能在实时编辑面板中稳定呈现，应在预览视图完整呈现、编辑视图保留原始语法。
5. 禁止用 `dangerouslySetInnerHTML` 接收未受限 HTML。要么使用受控服务端渲染的 HTML，并确保 MDX 安全策略明确；要么用受信任 React 内容组件渲染结果。

### 2.4 悬浮编辑器与保存

- 新 React 岛/弹窗可由静态 toolbar 按钮发送自定义事件打开，沿用 AI 面板“工具栏派发事件、岛自行管理状态”的模式，并兼容 `client:idle` 水合竞态及 Astro View Transitions。
- 考虑到首次点击必须可靠，可让随心录岛在拥有该权限时轻量加载，或在事件派发端补 readiness/重试机制；避免把大体积编辑器塞入所有游客首屏。
- 新建后生成稳定 ID；防抖自动保存沿用 `latest-save-queue` 的“只提交最新值”思路或同类队列。关闭前等待保存完成并处理失败重试；离页保护需避免挡住可预期导航。
- “快速记下”优先：弹窗打开后自动聚焦正文、默认隐藏非必要设置，标签可快捷录入；标题可以后补。

### 2.5 列表与筛选

- SSR 输出首屏卡片并校验权限，客户端用分页/加载更多；记录正文优先展示规范化渲染摘要或截断 HTML，避免超长内容撑满卡片。
- 标签筛选可参考 moments 的清洗规则；时间筛选可先由创建时间范围 SQL 过滤，再按年份/月份分组。标签条件与时间条件 AND 组合。
- 标签总览建议服务端分页/聚合得到真实全量标签，避免仅从当前页 DOM 收集导致遗漏。
- 新表进入 `src/sync/tables.ts`，确认桌面端离线 SQLite、生产 PostgreSQL 与同步引擎处理新增表的行为。

## 3. 主要技术风险与取舍

| 风险/决策 | 建议 |
|---|---|
| 编辑器与正式 MDX 能力不完全相同 | 把“预览完整一致”与“编辑态所见即所得”分开验收；实现前输出插件/语法矩阵，遇到不支持语法仍可编辑原文并在预览准确展示。 |
| 将“动态”或“日记”硬改为随心录 | 不推荐。动态的公开内容模型、日记的日期唯一约束都可能造成隐私或覆盖问题。用独立记录表语义清楚。 |
| 使用新的管理员权限 | 首期使用既有 `top` 身份，既不扩展授权配置，也不会随 `calendar` 权限向普通管理员开放。顶级管理员之间仍共享同一组随心录。 |
| 复用 Markdown 编译 | `renderMdx` 支持面最完整，但编译/组件能力也更复杂，卡片列表不应无界逐条重复编译；可按页限制数量并复用现有缓存，预览只编译当前一条。 |
| 桌面与云端一致性 | 同步配置和两套 schema 缺一不可；迁移需按仓库既有流程完成，避免本地表存在而 PG 缺失。 |
| 分享/访客账号 | 不纳入首期；若后续支持，必须将所有权从“全站一份笔记”改为 user_id/ACL，并重审 API 查询、缓存及桌面同步。 |

## 4. 推荐技术决定

首期已采用专用私密 `quick_notes` 表 + 顶级管理员会话 + 同源 `renderMdx`（经动态模块现有容错包装）+ 复用 `MarkdownEditor` + SSR 私密卡片页。记录创建时间负责时间线，标签数组负责分类。预览模式走正式渲染管线；编辑模式沿用 WYSIWYG，暂未覆盖的扩展保留源码编辑能力。
