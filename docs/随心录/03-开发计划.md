# 随心录开发计划

基于《01-需求文档》和《02-技术探讨》。2026-09-27 已完成首期功能代码与数据库接入；通过 Node 适配器本地服务完成桌面和窄屏浏览器验收。本文件保留阶段划分供后续迭代。

## 阶段 0：实现前确认与现状盘点

1. 已选择既有 `top` 身份保护随心录，顶级管理员共享记录，普通 `calendar` 管理员不可见。
2. 已选定稳定英文 URL `/quick-notes` 和对应 API 前缀。
3. 从 `mdx-plugins.ts`、MDX 组件注册表、`cm-wysiwyg.ts` 汇总扩展语法矩阵；标注正式预览支持与编辑中装饰支持。
4. 复核项目当前未提交工作，避免开发时覆盖用户现有改动；本文件与该功能专属分支/变更范围独立审阅。

**交付**：权限决策、路由决策、Markdown 覆盖清单。

## 阶段 1：数据与领域层

1. 在 SQLite 与 PostgreSQL schema 新增私密 `quick_notes` 表及字段/索引。
2. 新增领域访问层：创建、按 ID 读取、更新、删除、分页列表、时间范围、标签筛选和标签聚合。
3. 定义标题、正文、标签、分页边界的统一校验；保证更新时间在内容/标签更新时递增。
4. 在 `src/sync/tables.ts` 注册 LWW 同步表，并验证 desktop/local 与云端同步约定。
5. 执行对应 SQLite 与 PG schema migration 工作流，评估既有数据库部署方式。

**交付**：可在双方言保存和读取私密笔记的数据层。

## 阶段 2：权限与 API

1. 实现列表、详情、创建、更新、删除 API。
2. 在 `route-permissions.ts` 配置统一权限守卫；私密响应明确 `no-store`，校验错误返回结构与现有 API 一致。
3. 确保列表分页参数、内容体积和标签数量均有上限；未知 ID/越权不可泄漏记录是否存在的多余信息。
4. 预览请求使用同一 MDX 渲染管线；限定可用组件并确保输出处理与本站现有内容渲染安全边界一致。

**交付**：权限保护、私密缓存策略明确的记录 API。

## 阶段 3：快速记录悬浮窗

1. `RightToolbar.astro` 在 AI 按钮下增加随心录按钮，使用有语义的图标、aria-label、title 与既有焦点风格。
2. 增加悬浮记录器 React 岛：开窗即聚焦，支持新建/编辑、标题可选、标签输入、编辑/预览切换。
3. Markdown 输入复用 `MarkdownEditor`；正式预览调用权威 `renderMdx`，按语法覆盖矩阵对 CodeMirror 装饰差异作保守处理。
4. 增加防抖自动保存、保存状态、手动立即保存、失败重试、待保存关闭确认；新建记录创建后保留稳定 ID。
5. 处理 `client:idle` 首次点击、Astro View Transitions、桌面窄窗和移动端全屏布局。

**交付**：从任意页面打开即可捕获、编辑并保存想法的工具。

## 阶段 4：随心录浏览页

1. 新增 `/quick-notes` 私密页面；服务端鉴权、noindex、首屏 SSR。
2. 在 BaseLayout 顶栏“归档”右侧加入权限可见的“随心录”入口。
3. 用卡片展示时间、标题/摘要、标签和正文预览；按创建时间倒序，支持分页/加载更多。
4. 实现标签筛选、年/月/日期筛选、组合条件、空状态与清空筛选。
5. 点卡片进入悬浮编辑或页面编辑状态，保存后同步更新卡片和筛选结果。

**交付**：可回看、分类和按时间找回所有记录的私密页面。

## 阶段 5：验证与收尾

1. 鉴权检查：访客、无权限管理员、站主分别覆盖页面、列表/详情 API 和所有写操作。
2. 隐私检查：HTML 响应索引策略、API `Cache-Control`、预取/共享 CDN 不得泄漏内容。
3. Markdown 检查：GFM、数学、代码块、项目指令/Callout、注册组件及非法/不完整源码的编辑和预览表现。
4. 保存检查：新建、更新、连续快速输入、切换记录、网络错误、刷新、在途保存关闭。
5. 筛选检查：标签、年月/日期、组合、空结果、分页边界与全量标签。
6. 双方言与桌面同步检查：SQLite 本地、PostgreSQL migration、`src/sync/tables.ts` 及同步冲突策略。
7. 响应式与无障碍检查：主题/深色模式、键盘操作、移动端、Electron、View Transitions。
8. 依仓库约定运行类型检查、针对性测试和生产构建；核对工作区差异只含本功能预期改动，不覆盖已有未提交内容。
9. 更新文档和变更记录。

**交付**：可审查的完整实现与验证结果。

## 实施顺序与依赖

```text
权限/语法盘点
       ↓
数据模型 + 双方言 + 同步
       ↓
受保护 API + MDX 预览
       ↓
悬浮创建/编辑器 ───→ 卡片列表/标签时间筛选
       └───────────────→ 联调与隐私/兼容验证
```

可以并行讨论 UI 草图与语法覆盖矩阵，但代码阶段应先确定私密权限边界，再接入页面入口；若权限名单尚未确认，默认仅站主可访问，避免扩散私密记录。

## 模型选择与额度建议

### 本轮（需求文档、技术探讨、计划）

推荐 **GPT-6 Luna，medium**：本轮主要是静态仓库定位、现状归纳和结构化文档，没有需要大规模代码推理或复杂重构的工作。用中档推理足以保留项目关键细节，速度与额度更合适。

### 后续实施

推荐 **GPT-6 Sol，medium** 作为主力开发模型；只在 MDX 编辑器兼容、安全权限或双数据库迁移出现复杂边界问题时临时切到 **GPT-6 Astra，high** 做专项审查，再回到 Sol 完成修复。Astra 全程运行会为常规 UI/API/schema 编码消耗不必要的额度；Luna 独立承担完整实施则更省额度，但本功能横跨鉴权、渲染、双方言和桌面同步，遇到非局部问题时更容易增加往返次数。

若“最少额度”优先于过程速度，单模型方案选 **GPT-6 Sol，medium** 完成实施，不启用高档模型；复杂点用明确的阶段交付和专项审查提示控制返工。避免同时为 UI、API、schema 启动多个模型/agent，以免增加协调与上下文成本。

## 预估工作量

- 需求/权限/语法盘点：0.5–1 天
- 数据、API、双数据库与同步：1–2 天
- 悬浮编辑器与同源预览：1.5–3 天
- 私密卡片页与筛选：1–2 天
- 鉴权、桌面同步、Markdown 与响应式验证：1–2 天

约 **5–10 个工程日**，主要不确定性来自编辑器内全量扩展语法的覆盖边界和当前授权名单。若保持“正式预览全量同源、编辑器不支持语法保留源码”这一取舍，范围可控制在该区间下限附近。
