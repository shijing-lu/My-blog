# 笔记类型判定与规范化（note-normalizer）

**一句话职责**：识别类型 → 匹配骨架与强度 → 路由书写 → 输出「整理说明」。

本 skill 只做**判定与路由**，不重复排版语法；真正书写交给 `my-blog-structured-notes`。
两个 skill 串起来，就是「任意 TXT / 文本文档 → 一篇规范化笔记」的流水线。

---

## 0. 四条铁律

1. **不编造**：事实、数据、结论、引文一律来自原文，一个字都不添。
2. **缺失标注**：信息缺口用 `[待补]` 标出，不臆测填充。
3. **日记克制**：日记 / 随笔只做轻整理，不改语气与人称。
4. **必附说明**：输出末尾必须有「整理说明」，交代识别依据、路由与改动清单，可回退。

---

## 1. 处理流水线（六步）

1. **通读全文**：收集类型信号（第 3 节信号表），记录原文的编号体系、公式、代码、表格。
2. **判定类型**：强信号 ≥ 2 → 确认；强信号 1 + 弱信号 ≥ 2 → 倾向（向用户确认，推荐项排第一）；
   信号冲突或全部不足 → 问用户（附一句判断依据）。混合内容 → 定**主类型** + 子区段，不硬拆成两篇。
3. **选择强度**（第 2 节）：轻度 / 中度 / 重度；用户可指定覆盖。
4. **路由**：
   - 例题 / 题解 / 讲义 / 知识手册 / 词汇表 / 需要 My-Blog 扩展语法的长文 → **转 `my-blog-structured-notes`**（按其模式表选骨架）；
   - 会议记录 / 读书笔记 / 日记 / 通用文本 → 按第 4 节本 skill 的骨架整理。
5. **整理自检**：按该类型 checklist 逐条过，不过就回改。
6. **输出**：规范化笔记 + 「整理说明」（第 5 节）。

---

## 2. 整理强度分级

| 强度 | 做什么 | 不做什么 | 默认适用 |
| --- | --- | --- | --- |
| 轻度 | 排版规范化、错别字、分段、统一标点 | 不动内容结构 | 日记、通用兜底 |
| 中度 | 重组段落、补标题层级、统一术语、建立编号 | 不增删事实 | 会议记录、技术文档、读书笔记 |
| 重度 | 结构化重写、生成模板字段（行动项 / 自测卡 / 索引） | 事实仍须全部来自原文 | 学习笔记、知识手册、例题、词汇 |

**公共动作**：

- **术语统一**：同义异名归一；出现 ≥ 2 组时在文末附「术语对照」小表。
- **信息保全**：任何删减先在「整理说明」列改动清单；拿不准的一律进「待补项」。
- **公式与代码**：公式补 `$…$` / `$$…$$` 定界，命令进代码块；交 `my-blog-structured-notes` 时按其语法与自检执行。
- **答案遮罩**：原文「先问题、后答案」的结构，发布到 My-Blog 时可用 `:spoiler[答案]`（黑幕）或折叠卡承载，见书写 skill。

## 3. 类型识别信号表

| 类型 | 强信号（命中 ≥ 2 基本确认） | 弱信号 | 否定信号 |
| --- | --- | --- | --- |
| 技术文档 / 教程 | 命令行、代码块、安装配置、版本号、报错与解法、"步骤 1/2/3" | README、依赖、环境变量、截图 | 第一人称情绪叙事 |
| 知识手册（纯知识点） | 定义 / 定理 / 公式 / 性质成组出现、章节编号、考点标注、无例题 | 教材名、"第 X 章"、命题追踪 | 行动项、决议 |
| 例题 / 题解 | 题干 + 选项 A/B/C/D、"解 / 证明"、批注、考点、答案 | 讲义、"例 X.Y"、题型归纳 | 纯公式罗列（无题干） |
| 强化讲义 | 知识点 + 编号例题（例 1.x）+ 题型归纳 + 工具箱 / 二级结论 | "题型 N"、"方法"、"冲刺" | 只有定义无例题 |
| 词汇笔记 | 词条结构高度统一（词[音标] + 词性释义，一行为一词）、考点 / 派生 / 例句栏、按主题或字母序成表 | 词书名、List / Unit 编号 | 成段知识阐述、公式推导 |
| 读书笔记 | 书名 / 作者、章节摘录、引文 + 页码、"作者认为"、读后感 | 金句、ISBN / 豆瓣 | 决议、命令行 |
| 会议记录 | 出席 / 参会人、议程、决议、"行动项"、"负责人"、deadline | 时间地点、"讨论"、"同步" | 第一人称情绪叙事 |
| 日记 / 随笔 | 日期 + 第一人称、"今天"、情绪 / 心情 | 天气、流水账 | 术语公式密集 |
| 通用（兜底） | 以上强信号命中均 < 1 | — | — |

**判定输出要求**：每一步都要能说清「为什么判成这个类型」（引用命中的信号词），写进「整理说明」。

**判定示例**：

> 输入是一份 PowerShell 命令速查草稿：有 `Get-ChildItem`、`-Recurse` 等命令，有「版本 7.5.2」「执行策略」，
> 有「常见报错 → 解法」表 → 命中「命令行 / 代码块 / 版本号 / 报错」≥ 2 → **技术文档**；
> 但内容几乎全是命令族与知识点、没有连续叙事步骤 → 主类型定为「技术文档」，书写走知识手册模式。

## 4. 各类型骨架与规则

### 4.1 技术文档 / 教程

- **默认强度**：中度。
- **骨架**：概述（解决什么问题）→ 适用版本与环境前置 → 安装 / 配置 → 使用步骤（编号 + 代码块）→ 常见问题（报错 → 原因 → 解法）→ 参考。
- **规则**：命令一律进代码块保证可复制；版本敏感处标版本号；路径 / 占位符用 `<占位>`；同义术语归一。
- **自检**：每条命令都在代码块内；步骤可从头到尾照跑；报错条目含现象 + 原因 + 解法；版本明确或标 `[待补]`。
- **路由**：要发布到 My-Blog 且体量较大 → 交书写 skill，通常走「知识手册模式」（命令按族分组、
  加知识地图 / 速查表 / 必背清单 / 复习索引）；纯线性教程也可保留本文骨架、只借用其 Callout / 折叠语法。

### 4.2 学习笔记 / 知识手册

- **默认强度**：重度。
- **骨架**：核心问题 → 概念定义 → 方法 / 步骤 → 例题（保留原编号）→ 易错点 → 自测问题（3~5 个，检索式）。
- **规则**：概念首次出现补一句定义；相邻易混概念放进**同一个对照结构**；自测问题必须"合上笔记能作答"。
- **自检**：概念有定义；例题编号未丢失；易错点独立成区；自测问题全部为检索式。
- **路由**：发布到 My-Blog → 交书写 skill：纯知识点走「知识手册模式」，含例题走「例题模式」，
  知识点 + 例题 + 题型总结混合走「强化讲义模式」。

### 4.3 读书笔记

- **默认强度**：中度~重度。
- **骨架**：书目头（书名 / 作者 / 版本 / 阅读区间）→ 核心论点（≤ 3 条）→ 章节框架 → 摘录（引号 + 页码 / 章节）→ 我的评注 → 行动启发。
- **规则**：**摘录与评注严格分离**——摘录是"作者说的"，评注是"我想的"，不得混排；引文一字不改；
  评注缺失 → 留空区并标 `[待补]`，不代写。
- **自检**：每条摘录有出处；摘录与评注无混排；核心论点 ≤ 3 条；行动启发可执行。

### 4.4 会议记录

- **默认强度**：中度。
- **骨架**：

```markdown
# <会议主题>（<日期>）
- 时间 / 地点 / 参会人 / 记录人
## 议题与讨论
- <议题>：<要点>（口语转写为陈述句）
## 决议
- <决议>（依据：谁提出 / 是否一致同意）
## 行动项
| 事项 | 负责人 | 截止 |
| --- | --- | --- |
## 遗留问题
```

- **规则**：无明确结论的讨论标「结论待定」；行动项缺 owner / 期限 → `[待补]`；同一议题散落多处 → 合并；
  发言人观点保留归属（"X 提出…"）。
- **自检**：每个议题有归属段落；决议可追溯；行动项全部有 owner + deadline（或待补标记）；无口语残留（"然后""就是说"）。

### 4.5 日记 / 随笔

- **默认强度**：**轻度**（除非用户明确要求更深整理）。
- **骨架**：日期标题 + 原文正文（仅修错别字、分段）；可选末尾加一行标签（如 `#工作 #旅行`）。
- **规则**：**不重写、不改语气与人称、不加结构标题打断叙事**；不做情绪分析、不写总结评语；私密内容保持私密。
- **自检**：原文语句基本原样保留；未新增任何评价性文字；分段未改变叙述顺序。

### 4.6 通用（兜底）

- **默认强度**：轻度。
- **动作**：补标题层级、按主题分段、修错别字与标点、术语对照；正文超过 800 字补目录。
- **自检**：未重排事实顺序；未增删事实；标题层级 ≤ 3 级。

### 4.7 词汇 / 例题 / 知识手册 / 强化讲义

**直接路由**到 `my-blog-structured-notes`，本 skill 不重复它的骨架：
- 词汇表 / 单词书 → 其「背单词模式」；
- 单题逐篇例题 → 其「例题模式」（锁定模板）；
- 纯知识点 → 其「知识手册模式」；
- 知识点 + 例题 + 题型归纳 → 其「强化讲义模式」；
- 普通 MD 讲义要提升复习效率 → 其「转换模式」。

## 5. 输出格式

正文 = 规范化笔记（第 4 节骨架，或书写 skill 的骨架）。末尾追加「整理说明」，两种等价写法：

```markdown
> **整理说明**（AI 生成）
> - 识别类型：<类型>（置信度 高 / 中 / 低；依据：<命中的信号词>）
> - 路由：<本 skill 骨架 / my-blog-structured-notes 的哪个模式>
> - 整理强度：轻度 / 中度 / 重度
> - 主要改动：① … ② …（≤ 5 条）
> - 待补项：…（无则写"无"）
```

或作为独立小节（长文更易定位）：

```markdown
### 整理说明

> **整理说明**（AI 生成）
> - 识别类型：…
```

**真实项目里的写法**（可直接沿用）：识别类型写「技术文档（置信度 高；依据：…）」，
路由写「按 note-normalizer 的 X 规范取要素，按 my-blog-structured-notes 第 8 节『知识手册模式』组织排版」，
改动逐条编号，待补项写清「本篇不涉及 …」。

## 6. 交付前检查

- [ ] 「整理说明」齐全（识别类型 / 路由 / 强度 / 改动 / 待补）。
- [ ] 类型判断有信号依据，不是拍脑袋。
- [ ] 无编造事实；缺口都标了 `[待补]`。
- [ ] 路由正确：该走书写 skill 的没有硬套本 skill 骨架。
- [ ] 交书写 skill 时，已把原文的编号体系、公式、表格原样带过去。

---

## 7. 与书写 skill 的衔接

- 本 skill 输出「类型 + 强度 + 原文素材 + 整理说明草稿」；
  `my-blog-structured-notes` 负责骨架、语法、折叠 / 选项卡 / 高亮、渲染自检。
- 两 skill 的公共约定：**不编造、缺口标 `[待补]`、末尾必附整理说明**。
- 发布到 My-Blog 时，最终交付形态按书写 skill 的「交付」节执行（源文件 + 渲染自检 + 预览）。
