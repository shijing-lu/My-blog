# 站内文章结构样本与可复用片段

> 统计口径：本地库 30 篇 `articles`（2026-10 前），结构标记按源码正则统计。
> 用途：写新笔记时对照真实习惯；片段可直接复制改写。

## 2. 知识手册样本（PowerShell 手册）

**开篇**（一句话交代范围 + 编号体系 + 末尾有什么）：

```markdown
> [!info]【本篇说明】
> 本篇是一份 **PowerShell 命令行手册**，面向“平时查得快、上手就能用”：==主线是「管道里流的是对象，不是文本」==——
> 理解这一条，`Where-Object` / `Select-Object` / `Get-Member` 为什么长这样，全都顺了。
> 全篇两章共 21 个知识块（P1-01 ~ P1-09、P2-01 ~ P2-12），配 1 张命令速查表、1 份必背清单、4 张自测卡与复习索引。
> 所有命令都是**单行可直接粘贴**的写法；多行脚本另附「写法示例」代码块。
```

**章首知识地图 + 环境表**：

```markdown
## 【P1】入门：环境、命令与管道

### 适用环境与知识地图

**本机环境（实测）**

| 项目 | 值 |
| --- | --- |
| 当前版本 | PowerShell **7.5.2**（PSEdition = Core） |
| 执行策略 | `LocalMachine` = RemoteSigned |

**知识地图**

| 编号 | 类型 | 名称 |
| --- | --- | --- |
| P1-01 | 定义 | 什么是 PowerShell |
| P1-02 | 注 | 5.1 与 7.x 的差异与取舍 |
```

**知识块**（徽章 + 编号 + 名词化标题 + 高亮结论）：

```markdown
> [!note] 定义 P1-01｜什么是 PowerShell
> PowerShell 是==基于 .NET 的命令行 shell 与脚本语言==。
>
> - 传统 shell 的管道里流的是**文本**；
> - PowerShell 的管道里流的是**.NET 对象**。
>
> ==结论==：想筛数据用 `Where-Object`，想看结构用 `Get-Member`。

> [!warning] 注 P1-02｜5.1 与 7.x 的差异与取舍
> ==先看 `$PSVersionTable.PSEdition`：`Desktop` 是 5.1，`Core` 是 7.x==。
>
> | 特性 | 5.1 | 7.x |
> | --- | --- | --- |
> | `&&` 管线链 | 不支持 | 支持 |
```

**自测卡**（问题在标题、答案在卡内、末尾指回编号）：

```markdown
> [!question]- 自测：为什么脚本里的 `try/catch` 抓不住 `Get-Item` 找不到文件的报错？
>
> **【答案】** 那是非终止性错误，报告后继续执行、不进 `catch`；加 `-ErrorAction Stop` 或设
> `$ErrorActionPreference = 'Stop'`。（指回：P2-10、P2-11）
```

**末尾三件套**：`### 命令速查表`（主题｜命令｜编号）→ `> [!info]【必背清单】`（每条一个结论，配高亮）
→ `> [!info]【复习索引】`（钩子问题 + 指回 + 复习路径与间隔）。

**整理说明**：

```markdown
### 整理说明

> **整理说明**（AI 生成）
> - 识别类型：技术文档（置信度 高；依据：全篇为命令行、参数、版本号、报错与解法）
> - 路由：按 note-normalizer 的技术文档规范取要素，按 my-blog-structured-notes 第 8 节「知识手册模式」组织排版
> - 整理强度：中度（按命令族分组重排 ＋ 编号体系）
> - 主要改动：① 全篇拆为两章共 21 个知识块…；② 「公式速查」替换为「命令速查表」…；③ …
> - 待补项：本篇不涉及 PowerShell Remoting、Jobs、DSC…
```

## 3. 视频笔记 / 强化讲义样本（Remotion）

- 章标题用 `## 1 Remotion 是什么`（数字章，不用 `【】`），组内知识块用 `RM-01` 连续编号。
- 知识块按语义换徽章：定义 `[!note]+`、结论 `[!tip]+`、注 `[!warning]+`、口诀 `[!quote]+`、
  方法 `[!tip]`（不折叠）。
- 每个结论块末尾用一句高亮收束：

```markdown
> [!tip]+ 结论 RM-04｜Remotion 的主场：音画同步
> 典型例子是**音符跳跃动画**：光球随乐曲精准落在音符上。
>
> 这种「位置与轨迹高度同步」的效果，==单靠视频生成模型基本做不到=={.tip}；
> 而 Remotion 拿到曲谱 / MIDI 就能算出来。
>
> 判断口诀：**要跟着数据 / 音乐 / 时间轴走 → Remotion；要氛围与真实感 → 视频模型。**
```

- 末尾：指令速查表 + 必背清单 + 自测卡 + 复习索引。

## 4. 例题样本（线代旧稿 vs 锁定模板）

旧稿是「题目 + 解析批注 + 旁注/知识点」的松结构：

```markdown
## 【3.1】求解齐次方程组

**题目：**
…
**解析批注：**
…
> **旁注/知识点：**
> - 方法一：…
```

**新稿一律用锁定模板**（题干进折叠卡标题、解析内含关键点与思路分解、拓展知识出卡、末尾小结三 tabs）。
旧稿只作为素材来源，不直接沿用其结构。

## 5. 转换模式样本（Codex 使用技巧）

- 章内每节末尾加 `### 1.1 自测` + `> [!question]- 自测：…`，答案指回「第 1 节」。
- 用 `> [!info]- 订阅额度查看` 这类**默认收起**的信息卡承载次要细节。
- 全篇末尾 `> [!info]【复习索引】` 汇总钩子问题。

## 6. 部署教程样本（从零上线）

- `## 1 …` 数字章 + `### 1.1 …` 小节，长文以代码块与表格为主。
- 大量使用提示块与折叠：

```markdown
:::warning
<风险提示>
:::

:::collapse
- <常见问题>

  <解答>
:::

:::tabs#deploy-target

@tab:active Vercel

<步骤>

@tab 自建服务器

<步骤>

:::
```

- 危险操作单独用 `> [!danger]`，并在标题里写清后果。
